This note explains the math behind the Day 25 solution: how we map (row, col) to a 1‑D index along diagonals, and how we compute the code with modular exponentiation in O(log n) time.

## 1) Diagonal Indexing

The grid is filled by diagonals, starting at (1,1), then (2,1), (1,2), then (3,1), (2,2), (1,3), and so on. Every cell (row, col) lies on diagonal

- s = row + col − 1

The number of cells in diagonal k (1‑based) is k. The total number of cells in the first (s−1) diagonals is the triangular number

- T(s−1) = 1 + 2 + ··· + (s−1) = (s−1)·s / 2

Within diagonal s, the order runs upward to the right; the first cell on the diagonal is at column 1, the second at column 2, …, so the position within the diagonal is `col`. Therefore, the global 1‑based index n for (row, col) is

- n = T(s−1) + col = ((s−1)·s)/2 + col, where s = row + col − 1

Example (from the prompt): row = 2981, col = 3075
- s = 2981 + 3075 − 1 = 6055
- T(s−1) = (6054 · 6055)/2 = 18,328,485
- n = 18,328,485 + 3,075 = 18,331,560

This matches the code’s `index_for(row, col)` function.

---

## 2) Code Generation as a Modular Recurrence

Codes are generated by a multiplicative recurrence modulo a prime-like modulus:
- START at n = 1: `20151125`
- For n > 1: `code(n) = (code(n−1) × 252533) mod 33554393`

By induction, this yields a closed form:
- `code(n) = START × 252533^(n−1) mod 33554393`

So, once we map (row, col) → n, we only need to compute a modular power `252533^(n−1) (mod 33554393)` and multiply by START under the same modulus.

---

## 3) Modular Exponentiation (Why O(log n))

We compute `a^e mod m` with exponentiation by squaring:
- Maintain `acc = 1`, `base = a`, `exp = e`
- While `exp > 0`:
  - If the least significant bit of `exp` is 1, set `acc = (acc × base) mod m`
  - Square the base: `base = (base × base) mod m`
  - Shift exponent: `exp >>= 1` (divide by 2)

This processes one bit of the exponent per iteration. If `e` is roughly `n`, the time is O(log2 e), i.e. about the number of bits in `e`.

For the example input index `n − 1 = 18,331,559`, `log2(18,331,559) ≈ 24.1`, so ~25 iterations, each doing up to two modular multiplies. This is trivially fast.

Implementation details:
- We use `u128` intermediates for `a*b` before reducing mod `m` to avoid overflow, then cast back to `u64`.
- Even `u64` would suffice here because `m^2 < 2^64`, but `u128` is a safe general choice.

---

## 4) Putting It Together

- Given `(row, col)`, compute `s = row + col − 1` and `n = ((s−1)·s)/2 + col`.
- Compute `pow = 252533^(n−1) mod 33554393` via fast exponentiation.
- Code at `(row, col)` is `(20151125 × pow) mod 33554393`.

This avoids iterative stepping through all previous codes and runs in logarithmic time with respect to the index.

## 6) Why This Is Correct

- Diagonal mapping uses a well-known triangular-number count for items in diagonals; the closed form derives directly from the sum of the first `s−1` integers.
- The recurrence is linear in the multiplicative group modulo `m`; since it’s `code(n) = START × MUL^(n−1) mod m`, modular exponentiation gives the exact value.
- All arithmetic is performed under modulus, so intermediate values remain bounded and the algorithm is stable and fast.
