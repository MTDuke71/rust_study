## 🔧 **Key Learnings**

**Ch2 Deep Insights**:
- **Memory Layout**: `repr(C)` for FFI, `repr(packed)` risks, `repr(transparent)` for newtypes
- **Dispatch Trade-offs**: Static (fast, large binary) vs Dynamic (flexible, vtable overhead)
- **Orphan Rule**: Can implement trait if trait OR type is local, with covered implementation exception
- **HRTB**: `for<'a>` enables lifetime-generic bounds (common with Fn traits)
- **Type-State Pattern**: Zero-sized marker types enforce compile-time state machines
- **impl Trait**: Zero-cost abstraction - compiler knows concrete type, user sees trait
- **Wide Pointers**: DSTs require 2×usize (slice: ptr+len, trait object: ptr+vtable)

**Mission 11 Deep Insights**:
- Memoization transforms O(P^L) exponential → O(P×L) linear
- Lifetime parameters `<'a>` enable zero-copy HashMap keys (borrowed from input)
- Boolean existence checks mechanically transform to exhaustive counting
- Top-down (memoization) vs bottom-up (tabulation) trade-offs
- Generic `MemoCache<K, V>` pattern reusable across many problems

**Ch1 → Mission 11 Connection**:
- Ch1.3 lifetime knowledge directly applied in Step 3
- Borrowing rules prevent dangling cache references
- Compiler enforces memory safety in recursive caching
