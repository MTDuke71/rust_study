### Problem 8: Largest Product in a Series ✅

**Challenge**: Find the thirteen adjacent digits in a 1000-digit number with the greatest product.

**Solution**:
- **Answer**: 23,514,624,000
- **Algorithm**: Sliding window with zero-skipping optimization
- **Performance**: ~2.97 μs (Criterion benchmark)
- **Complexity**: O(n × k) where n=1000, k=13

**Key Implementation**:
```rust
pub fn largest_product_in_series(number: &str, window_size: usize) -> u64 {
    let digits: Vec<u64> = number.chars()
        .filter_map(|c| c.to_digit(10))
        .map(|d| d as u64)
        .collect();
    
    // Slide window with zero-skipping optimization
    for window_start in 0..=digits.len() - window_size {
        let window = &digits[window_start..window_start + window_size];
        if window.contains(&0) { continue; }  // Optimization!
        
        let product = window.iter().product::<u64>();
        max_product = max_product.max(product);
    }
}
```

**Insights**:
- Zero-skipping: Check adds O(k) overhead but saves k multiplications when zeros present
- Trade-off analysis: roughly equal cost, but clearer code intent
- Rust `.windows()` iterator provides safe, zero-copy slicing

### Problem 9: Special Pythagorean Triplet ✅

**Challenge**: Find the unique Pythagorean triplet where a + b + c = 1000, return product abc.

**Solution**:
- **Answer**: 31,875,000
- **Triplet**: (200, 375, 425) = 25 × (8, 15, 17)
- **Verification**: 200² + 375² = 40,000 + 140,625 = 180,625 = 425² ✓
- **Algorithm**: Constrained search with mathematical bounds
- **Performance**: ~45.5 μs

**Mathematical Analysis**:
- Triplet is **non-primitive** (scaled by k=25)
- Primitive base: (8, 15, 17) from Euclid's formula with m=4, n=1
- Perimeter of primitive: 8 + 15 + 17 = 40
- Scaled perimeter: 25 × 40 = 1000 ✓

**Bound Optimization**:
```rust
// Exploiting constraints a < b < c and a + b + c = 1000
for a in 1..target/3 {                    // a < 333 (not 1000!)
    for b in (a+1)..=(target-a)/2 {       // b < (1000-a)/2
        let c = target - a - b;            // c determined
        if a*a + b*b == c*c { return (a,b,c); }
    }
}
```

**Complexity reduction**: 1,000,000 → 83,250 operations (12× improvement)

### Euclid's Formula Deep Dive 📐

**Discovered fundamental theorem** for generating Pythagorean triplets:

$$a = k(m^2 - n^2), \quad b = k(2mn), \quad c = k(m^2 + n^2)$$

**Conditions** for primitive triplets:
- $m > n > 0$ (ensures positive a)
- $\gcd(m, n) = 1$ (coprimality ensures primitivity)
- $m - n$ is odd (not both odd, to avoid common factor of 2)

**Examples verified**:
- m=2, n=1 → (3, 4, 5) ✓
- m=3, n=2 → (5, 12, 13) ✓
- m=4, n=1 → (8, 15, 17) ✓
- m=4, n=3 → (7, 24, 25) ✓

**Perimeter formula**: P = 2m(m + n)

**Completeness**: Euclid's formula generates **all** primitive triplets exactly once!

## 🔧 **Technical Insights**

### 1. Sliding Window Pattern Mastery

**Core technique**: Process contiguous subsequences efficiently
- **Fixed window**: O(n × k) naive → O(n) with incremental updates
- **Variable window**: Two-pointer technique with O(n) complexity
- **Applications**: String processing, time series, rate limiting

**Optimization strategies**:
- Incremental updates: sum = sum - left + right (O(1) per iteration)
- Early termination: Skip windows failing conditions
- Precomputation: Prefix sums for range queries

### 2. Mathematical Constraint Exploitation

**Pattern**: Transform constraints into search space reduction

**Example from P9**:
- Constraint: a + b + c = 1000
- Insight: c = 1000 - a - b (eliminates one variable)
- Bound: a < 1000/3 (from a < b < c)
- Impact: 3D search → 2D search with tight bounds

**Lesson**: Analyze constraints mathematically **before** coding!

### 3. Algorithm Selection Framework

**Decision criteria**:

| **Problem Size** | **Algorithm** | **Justification** |
|------------------|---------------|-------------------|
| n ≤ 10,000 | Constrained brute force | Simple, fast enough (~ms) |
| n > 10,000 | Euclid's formula | Better scaling O(n) vs O(n²) |
| Real-time | Precomputed lookup | O(1) query after O(n) preprocessing |

**Principle**: Choose simplest algorithm that meets performance requirements.

### 4. Type-Safe Domain Modeling

**Design pattern**: Encode invariants in types

```rust
pub struct PythagoreanTriplet {
    pub a: u32, pub b: u32, pub c: u32,
}

impl PythagoreanTriplet {
    pub fn new(a: u32, b: u32, c: u32) -> Option<Self> {
        if a < b && b < c && a*a + b*b == c*c {
            Some(Self { a, b, c })
        } else {
            None
        }
    }
}
```

**Benefits**:
- Validation enforced at construction
- Methods: `.sum()`, `.product()` encapsulated
- Can't accidentally create invalid triplet
- Self-documenting code

### 5. Integer Arithmetic Precision

**Lesson**: Prefer integer operations over floating-point when possible

❌ **Floating-point** (precision issues):
```rust
let c = ((a*a + b*b) as f64).sqrt() as u32;
```

✅ **Integer-only** (exact):
```rust
let c = 1000 - a - b;
if a*a + b*b == c*c { /* exact comparison */ }
```

**Why**: Avoids rounding errors, guarantees correctness
