## Technical Notes
- **Y-up at parse time**: the puzzle talks about "facing up"; screen rows
  increase downward. Flip the y-axis in `parse_input` (`y = cy - row`) so
  `dir = (0, 1)` genuinely means up. Every downstream turn/move reads like
  the puzzle description with no sign-bending.
- **Turn primitives**: `right: (dx,dy) → (dy,-dx)`, `left: (dx,dy) → (-dy,dx)`,
  `reverse: (dx,dy) → (-dx,-dy)`. Three one-liners replace a
  `match direction` with four arms.
- **Part 1 is sparse, Part 2 is dense**: Part 1 keeps `HashSet<(i32,i32)>`
  (final live cells ~a few thousand, 10k bursts finishes in ~320µs).
  Part 2 swaps to a flat `Vec<u8>` bounded 1024×1024 (1 MiB) so each of the
  10M bursts does one direct index instead of a hash-and-probe.
- **State machine as modular arithmetic**: the Part 2 transitions form a
  cycle (Clean→Weakened→Infected→Flagged→Clean), so `next = (state + 1) & 0b11`
  replaces a 4-arm transition match. "Caused an infection" is exactly
  `next == INFECTED` — one compare per burst, no extra tracking.
- **Parse-once honored**: `solve()` parses once and calls both
  `_with_data` helpers. Combined (53.87ms) < sum of individual parts
  (55.32ms) as the repo's convention asks.

## Key Insight
**If you can bound the domain, flatten it.** Part 2's `HashMap<(i32,i32), State>`
draft would run ~2 seconds — 20 million hash-and-probe ops at ~50–100 ns each.
Swapping to a 1024×1024 flat `Vec<u8>` dropped that to ~55 ms. The hash wasn't
the algorithm; it was an indirection that dominated because the iteration count
was 10⁷+. The deciding question is never *"is hashing slow"* but *"is my domain
bounded enough to flatten"* — and for the Sporifica virus the carrier never
drifts more than a few hundred cells from origin, so 1 MiB of RAM gives O(1)
access with a tiny constant.

The same instinct explains counting sort beating comparison sort for small
alphabets, bitset-over-HashSet for dense integer sets, and direct-indexed LUTs
over HashMaps in Day 21's bit-packed variant. It's the integrator move:
recognize that your working set fits in a static arena, and trade memory for
time.

The second integrator move was keeping the state machine uniform. Four states
that *always* advance by +1 is just modular arithmetic. The turn rule varies
per state and stays in a `match`; the state rule doesn't, so it doesn't. Not
every pattern simplifies — but this one did, and noticing made the inner loop
five branches on turn plus one add-mask-compare for the rest.
