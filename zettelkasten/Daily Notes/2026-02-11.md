### VecDeque for FIFO Queue
**Pattern**: Items inspected in arrival order (first-in, first-out)

**Data structure choice**:
```rust
items: VecDeque<u64>

// Efficient FIFO (both O(1) amortized)
items.pop_front()   // Inspect oldest item
items.push_back()   // Add new item to back
```

**Why not Vec**:
```rust
// Vec::remove(0) is O(n) - shifts all elements
// VecDeque::pop_front() is O(1) - no shifting
```

**Performance impact**: O(n²) → O(n) for item processing

### Clippy Allowed: Needless Range Loop
**Issue**: Clippy suggests using iterator instead of index loop
```rust
for monkey_idx in 0..game.monkeys.len() {  // Clippy warning
    // Access multiple monkeys during iteration
}
```

**Why we need index**:
- We mutate `game.monkeys[monkey_idx]` to take items
- We push items to `game.monkeys[target]` (different index)
- Can't use `.iter_mut()` - would borrow entire vector
- Need simultaneous access to multiple elements

**Solution**: Justified `#[allow]` with comment
```rust
#[allow(clippy::needless_range_loop)]
for monkey_idx in 0..game.monkeys.len() {
    // Mutating game.monkeys while accessing multiple indices
}
```

## 🎓 **Mathematical Concepts**

### Chinese Remainder Theorem (CRT)
**Theorem**: Given coprime moduli m₁, m₂, ..., mₙ and any remainders r₁, r₂, ..., rₙ, there exists unique solution x (mod M) where M = m₁ × m₂ × ... × mₙ

**Day 11 application**:
- Want to preserve divisibility tests for d₁, d₂, ..., d₈
- Use modulo M = d₁ × d₂ × ... × d₈
- For any worry value w: `(w % M) % dᵢ == w % dᵢ` for all i
- Keeps w bounded while preserving all test results

**Why it works here**:
- Divisors likely coprime by puzzle design (11, 19, 5, 3, 13, 17, 7, 2)
- Product = 9,699,690 (all worry values stay < 10 million)
- No overflow for 10,000 rounds

**Related**: [[zettelkasten/math-foundations/chinese-remainder-theorem]] (if created)

### Modular Arithmetic Properties
**Key properties used**:
1. `(a + b) % m = ((a % m) + (b % m)) % m`
2. `(a × b) % m = ((a % m) × (b % m)) % m`
3. `a % m₁ == b % m₁ ∧ a % m₂ == b % m₂ ⟹ a % (m₁ × m₂) == b % (m₁ × m₂)` (if coprime)

**Application**: After applying monkey's operation, apply modulo - all future divisibility tests remain valid.
