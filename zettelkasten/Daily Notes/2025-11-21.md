#### 3. Understanding async/await Mechanics

- **Waker Pattern**: How `select!` detects channel activity
  - Futures register `Waker` when returning `Poll::Pending`
  - Channel calls `waker.wake()` when message arrives
  - Runtime re-polls the awakened future
  - First ready branch wins, others dropped
- **Loop + select! + break Pattern**: Graceful cancellation
  - Loop creates fresh futures each iteration
  - `select!` polls all branches
  - `break` in cancellation branch exits loop
  - Allows cleanup before task shutdown

### 🔑 Key Concepts Mastered

#### Sequential vs Concurrent Execution

| Pattern | Structure | Timing |
|---------|-----------|--------|
| **Sequential** | 1 `tokio::spawn` with async block | Additive: 300ms + 200ms = 500ms |
| **Concurrent** | 2 `tokio::spawn` tasks | Parallel: max(300ms, 200ms) = 300ms |

**Insight**: Receiver logic stays identical - only sender structure changes!

#### Channel Usage Patterns

| Purpose | Type | Example |
|---------|------|---------|
| **Data Transfer** | `mpsc::channel<T>` | Sending i32, String values between tasks |
| **Control Signaling** | `mpsc::channel<()>` | Graceful cancellation, shutdown coordination |

#### Graceful vs Abrupt Cancellation

- **Abrupt**: `drop(handle)` - immediate stop, no cleanup
- **Graceful**: Channel message → task detects in `select!` → cleanup → `break`

### 🔧 AUTOSAR Analogies Applied

- Sequential task = one runnable doing steps in order
- Concurrent tasks = two separate runnables scheduled by RTE
- `select!` = RTE checking multiple event flags, processing first ready
- Waker = event flag that triggers runnable activation
- Graceful shutdown = checking flag and cleanup vs killing runnable
