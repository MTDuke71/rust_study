### Mission 11: REQ-2 Top-Down DP Pattern

**The Canonical 4-Step Template:**
```rust
fn solve<'a>(state: &'a State, memo: &mut HashMap<&'a State, Result>) -> Result {
    // 1. Base case - Stop recursion
    if is_base_case(state) { return base_value(); }
    
    // 2. Cache check - Already solved?
    if let Some(&cached) = memo.get(state) { return cached; }
    
    // 3. Recursion - Solve subproblems
    let result = combine_subproblems(state, memo);
    
    // 4. Cache & return - Store for future hits
    memo.insert(state, result);
    result
}
```

**Key Insight**: Boolean→Counting transformation requires **zero structural changes**. Only the reduction operator changes:
- Boolean: Early-exit **OR** (`if any { return true }`)
- Counting: Accumulative **SUM** (`total += subproblem`)
- Structure: **IDENTICAL**

### Rust for Rustaceans: Ch3 Flexible Part 2 (pp. 45-46) - Borrowed vs. Owned, Fallible Destructors

• **Borrowed vs. Owned Data**: Interfaces should generally **operate on references** if they do not need ownership. If your code _does_ need ownership, it should **require owned data from the caller** rather than taking a reference and cloning it; this makes the cost of allocation explicit. For cases where ownership is only needed sometimes based on runtime conditions, the **Cow** **(Clone-on-Write) type** is a flexible tool for return types.

• **Fallible and Blocking Destructors**: The `Drop` trait is restrictive because it cannot return errors or handle asynchronous cleanup. To provide a more flexible teardown, interfaces for types involving I/O should offer an **explicit destructor** (a method that takes `self` and returns `Result`) for graceful cleanup, while using `Drop` as a "best-effort" fallback.

Designing a flexible interface is like **writing a legal contract with a "low bar" for entry but a "high bar" for your own performance**: you want to make it as easy as possible for others to sign on (relaxed requirements) while ensuring you don't over-promise things you might want to change later (stable promises).
