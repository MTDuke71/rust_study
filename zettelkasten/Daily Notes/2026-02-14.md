## 🎯 Problem Summary

**Day 14: Regolith Reservoir** - Simulate falling sand with physics-based settling

**Input**: Rock structure paths in (x,y) format
```
498,4 -> 498,6 -> 496,6
503,4 -> 502,4 -> 502,9 -> 494,9
```

**Sand Physics Rules** (try in order):
1. **Down**: `(x, y+1)` - Falls straight down if air
2. **Down-left**: `(x-1, y+1)` - If blocked, try diagonal left

4. **Rest**: If all three blocked, sand comes to rest

### Part 1: Sand Simulation with Abyss Detection

**Algorithm**: Iterative sand dropping
```rust
pub fn part1(data: &ParsedData) -> usize {
    let mut grid = data.grid.clone();
    let mut count = 0;

    while drop_sand(&mut grid, data.source, data.max_y) {
        count += 1;
    }

    count
}

fn drop_sand(grid: &mut Grid<Tile>, source: Coord, max_y: usize) -> bool {
    let mut pos = source;

    loop {
        match try_move_sand(grid, pos) {
            Some(next) => {
                if next.y > max_y {
                    return false;  // Fell into abyss!
                }
                pos = next;
            }
            None => {
                grid[pos] = Tile::Sand;
                return true;  // Came to rest
            }
        }
    }
}
```

**Key insights**:
- **try_move_sand()** encapsulates physics rules (down, down-left, down-right)
- **Early termination**: First sand unit below max_y ends simulation
- **Mutation**: Grid state tracks settled sand
- **Underflow protection**: Check `x > 0` before `x - 1` (usize safety)

**Part 1 result**: 763 sand units

### Part 2: Infinite Floor and Pyramid Spread

**Challenge**: Sand spreads in pyramid shape, need wider grid

**Pyramid Math**:
```
Floor at y = max_y + 2
Maximum horizontal spread = floor_y distance from source
Each level down allows ±1 horizontal movement

Example (max_y=9, floor=11):
y=0:  .......+.......   ← Source (1 position)
y=1:  ......ooo......   ← ±1 spread (3 positions)
y=2:  .....ooooo.....   ← ±2 spread (5 positions)
...
y=11: ooooooooooooooo  ← ±11 spread (23 positions)
```

**Grid Expansion Strategy**:
```rust
pub fn part2(data: &ParsedData) -> usize {
    let floor_y = data.max_y + 2;

    // Sand can spread floor_y distance in both directions
    let left_padding = floor_y;
    let right_padding = floor_y;
    let width_needed = data.grid.width() + left_padding + right_padding;

    let mut grid = Grid::new(width_needed, floor_y, Tile::Air);

    // Copy rocks with offset
    for y in 0..data.grid.height() {
        for x in 0..data.grid.width() {
            grid[Coord::new(x + left_padding, y)] = data.grid[Coord::new(x, y)];
        }
    }

    // Adjust source position
    let new_source = Coord::new(data.source.x + left_padding, data.source.y);

    let mut count = 0;
    while drop_sand_with_floor(&mut grid, new_source, floor_y) {
        count += 1;
    }

    count
}
```

**Key insights**:
- **Dynamic padding**: Calculate based on floor_y, not fixed constant
- **Best of both worlds**: Minimal grid (Part 1) + pyramid accommodation (Part 2)
- **Source blockage**: Termination when `grid[source] == Tile::Sand`
- **Floor logic**: Sand rests when `pos.y + 1 == floor_y`

**Memory efficiency**:
```
Naive approach:  601 × 160 = 96,160 cells
Smart approach:   89 + 160 + 160 = 409 width → 409 × 160 = 65,440 cells
Savings: 30,720 cells (32% reduction)
```

**Part 2 result**: 23,921 sand units

### Physics Simulation Pattern

**Clean separation** of concerns:
```rust
// Pure physics rules (no termination logic)
fn try_move_sand(grid: &Grid<Tile>, pos: Coord) -> Option<Coord> {
    // Try down
    let down = Coord::new(pos.x, pos.y + 1);
    if down.y < grid.height() && grid[down] == Tile::Air {
        return Some(down);
    }

    // Try down-left (underflow protection!)
    if pos.x > 0 {
        let down_left = Coord::new(pos.x - 1, pos.y + 1);
        if down_left.y < grid.height() && grid[down_left] == Tile::Air {
            return Some(down_left);
        }
    }

    // Try down-right
    let down_right = Coord::new(pos.x + 1, pos.y + 1);
    if down_right.x < grid.width() && down_right.y < grid.height()
        && grid[down_right] == Tile::Air {
        return Some(down_right);
    }

    None  // Sand comes to rest
}

// Part 1: Abyss termination
fn drop_sand(...) -> bool { /* check y > max_y */ }

// Part 2: Floor + source blockage termination
fn drop_sand_with_floor(...) -> bool { /* check floor and source */ }
```

**Benefits**:
- **Reusable physics**: Both parts use same `try_move_sand()`
- **Testable logic**: Physics rules independent of termination
- **Clear structure**: Each function has single responsibility

### Underflow Protection - Critical for usize Arithmetic

**The problem**:

**The solution**:


**Lesson**: usize arithmetic requires explicit bounds checks. The compiler won't save you here!

### 3. Pyramid Spread Requires Mathematical Insight

**The physics**:
- Sand falls diagonally (down-left or down-right)
- Each vertical level allows ±1 horizontal movement
- Maximum depth = floor_y = max_y + 2
- Therefore, maximum horizontal spread = floor_y in each direction

**The math**:
```
Depth = floor_y
Max left spread = floor_y
Max right spread = floor_y
Width needed = original_width + 2 × floor_y
```

**Example** (max_y=9):
```
floor_y = 11
Source at normalized x=8
Can reach: x ∈ [8-11, 8+11] = [-3, 19]
With Part 1 width=14: Need padding ±11 → width = 14 + 22 = 36 ✅
```

**Lesson**: **Physics constraints** drive data structure sizing. Model the problem, don't guess dimensions!

### 4. usize Underflow is Silent and Deadly

**The trap**:
```rust
let x: usize = 0;
let left = x - 1;  // Wraps to usize::MAX (18,446,744,073,709,551,615)
// No panic in release mode! Silently wrong answer.
```

**The protection**:
```rust
if x > 0 {  // Explicit bounds check FIRST
    let left = x - 1;  // Now safe
}
```

**Where this bit us**:
- Initial test failed with underflow in `try_move_sand()`
- `test_sand_spreads_diagonally` hung (infinite loop from wrapped coordinate)
- Fixed by adding `if pos.x > 0` guard

**Lesson**: **usize is not a natural number** - it wraps! Always bounds-check before subtraction.

## 📚 Mathematical Concepts Applied

### Coordinate Transformations

**Affine transformation**: `x' = x - offset`

**Properties**:
- **Bijective**: Every original coord maps to exactly one normalized coord
- **Distance-preserving**: |x₁ - x₂| = |x₁' - x₂'|
- **Invertible**: `x = x' + offset` (can recover original)

**Application**: Minimize grid while preserving spatial relationships

---

### Pyramid Growth (Arithmetic Sequence)

**Horizontal spread at depth d**: `[-d, +d]` → width = 2d + 1

**Cumulative growth**:
```
d=0: 1 position  (just source)
d=1: 3 positions (±1 from source)
d=2: 5 positions (±2 from source)
...
d=n: 2n+1 positions
```

**Sum (pyramid volume)**: Σ(2d+1) for d=0 to n = (n+1)²

**Application**: Part 2 has max_y=158, floor_y=160
- Theoretical max sand: (160+1)² = 25,921 positions
- Actual result: 23,921 sand units (92% filled)
