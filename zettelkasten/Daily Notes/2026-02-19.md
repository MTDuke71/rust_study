## Day 19: Not Enough Minerals

**Problem**: Given 30 robot blueprints, maximize geode production by choosing which resource-collecting robots to build. 4-tier resource chain: ore → clay → obsidian → geodes.

### Results
- **Part 1**: 1,413 (quality level sum, 30 blueprints × 24 min) - 1.92ms
- **Part 2**: 21,080 (geode product, 3 blueprints × 32 min) - 1.56ms
- **Combined**: 3.50ms

### Algorithm: DFS with Branch-and-Bound

Explicit stack-based DFS with **skip-to-build** strategy:

1. **Skip-to-build**: Instead of deciding each minute (build or wait), compute exactly when enough resources accumulate for each robot type and jump to that future state. Collapses branching from 5 choices/minute to at most 4 meaningful build decisions per state.

2. **Robot caps**: Never build more robots of a type than the max spend rate per minute. Building 5 ore robots when max ore cost is 4/min wastes a turn.

3. **Triangle upper bound**: Even if we built a geode robot every remaining minute: `geodes + r_geo * time + time*(time-1)/2`. If this can't beat current best, prune entire subtree.

4. **Prerequisite guards**: Can't build obsidian robots without clay production (`r_clay > 0`), can't build geode robots without obsidian production (`r_obs > 0`).

### Key Insight: Skip-to-Build Eliminates Exponential Idle Turns
Without skip-to-build, the search tree has branching factor ~5 at each of 24-32 minutes — trillions of states. Skip-to-build eliminates "do nothing" turns entirely, producing only ~thousands of meaningful states per blueprint.

## Patterns Worth Remembering

- **Skip-to-build**: Don't branch on "build or wait" each tick — compute wait time with `.div_ceil()` and jump forward. Applicable to any resource-gathering optimization.
- **Robot caps from max spend rate**: `max_ore_cost = max(all ore costs)` — never build more producers than you can spend per turn.
- **Triangle number upper bound**: `n*(n-1)/2` new production if you build a robot every remaining turn. Tight enough to prune most of the search tree.
- **Type aliases for clippy**: Complex tuples → named type aliases. Consistent pattern across Day 17 and Day 19.
