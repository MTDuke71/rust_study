## Day 20: Grove Positioning System

**Problem**: Mix a circular list of numbers where each element moves forward or backward by its own value, then extract coordinates from positions relative to the zero element.

### Results
- **Part 1**: 8,028 (1 mixing round, 5,000 elements) - 5.72ms
- **Part 2**: 8,798,438,007,673 (10 rounds × decryption key 811,589,153) - 59.49ms
- **Combined**: 65.46ms

### Algorithm: Index-Tagged Circular Mixing

Three critical insights power the solution:

1. **Index tagging with `enumerate()`**: Elements are tagged as `(orig_idx, value)` to handle duplicate values. Without this, `.position()` finds the wrong element when duplicates exist.

2. **Modulus n-1, not n**: After removing an element, the circular list has n-1 gaps for reinsertion. Using `% n` causes off-by-one errors at boundary positions.

3. **Double-modulus for negative values**: Rust's `%` is remainder (can be negative), not true modulus. Pattern: `((pos + val) % modulus + modulus) % modulus` guarantees non-negative result.

### Key Insight: O(n²) Vec Operations Are Acceptable Here
With n=5,000 elements and 10 rounds, the O(n²) Vec `remove()`/`insert()` approach takes 65ms. More sophisticated data structures (BTreeMap, linked list) would add complexity for marginal gain. The 1-second budget has plenty of room at 89.30ms cumulative.

## Patterns Worth Remembering

- **Index tagging**: `enumerate().collect()` to track original positions through mutations. Essential whenever duplicates exist and order matters.
- **Mod n-1**: When removing-then-reinserting in a circular list, the gap count is n-1. This off-by-one is the #1 source of bugs in circular list problems.
- **Double modulus**: `((x % m) + m) % m` — memorize this pattern for any time Rust's `%` might produce negative remainders.
- **O(n²) is fine sometimes**: Vec remove/insert at 65ms for n=5,000 × 10 rounds. Don't over-optimize when the budget allows it.
