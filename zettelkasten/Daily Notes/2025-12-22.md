## 🔧 **Technical Insights**

### Axum Extractors Pattern
- **State<AppState>**: Shared application state (Arc-cloned automatically)
- **Path<Uuid>**: URL path parameter extraction with automatic validation
- **Json<T>**: Request body deserialization with type safety
- **Type Safety**: Axum rejects invalid requests before handler runs (400 Bad Request)

### Error Handling in Axum
- Automatic JSON parsing errors provide detailed messages (e.g., "key must be a string at line 1 column 2")
- Custom error_response helper function for business logic errors
- HTTP status codes: 200 OK, 201 Created, 204 No Content, 400 Bad Request, 404 Not Found

### PowerShell vs Bash
- Line continuation: `` ` `` (PowerShell) vs `\` (bash)
- Variables: `$VAR = value` vs `export VAR=value`
- JSON extraction: `ConvertFrom-Json` vs `jq`
- Silent mode: `curl -s` hides progress meter (% Total, % Received, etc.)

### State Management Insights
- `Arc<Mutex<HashMap<Uuid, UnionFind>>>` enables concurrent request handling
- Closure pattern encapsulates mutex lifetime for clean API
- RAII ensures automatic lock release
- `Option<R>` pattern handles missing instances gracefully

### Bron-Kerbosch Algorithm (AoC Day 23)
- **Maximum clique problem**: Find largest fully connected subgraph (NP-complete)
- **Three sets**: R (current clique), P (candidates), X (excluded/processed)
- **Pivoting optimization**: Only explore nodes NOT connected to pivot (dramatically reduces search space)
- **Base case**: When P=∅ and X=∅, R is a maximal clique
- **Recursive pattern**: Add candidate to R, filter P and X to neighbors, recurse, then move candidate from P to X
- **Set operations**: Union (P ∪ X), Intersection (P ∩ N(v)), Difference (P \ N(pivot))
- **Performance**: < 100ms for 520 nodes, 3380 edges (finds 13-node maximum clique)
