## 🎯 Problem Summary

**Day 13: Distress Signal** - Compare and sort nested list packets

**Input**: Pairs of nested list packets (JSON-like format)
```
[1,1,3,1,1]
[1,1,5,1,1]

[[1],[2,3,4]]
[[1],4]
```

**Comparison Rules**:
1. **Both integers**: Lower integer comes first
2. **Both arrays**: Compare element-by-element, shorter wins if all match
3. **Mixed types**: Convert integer to `[integer]` and retry comparison

**Parts**:
- Part 1: Sum indices (1-based) of pairs already in right order → **5852**
- Part 2: Sort all packets + divider packets `[[2]]` and `[[6]]`, find decoder key → **24190**

### Part 1: Recursive Comparison Implementation

**Algorithm**: Pattern matching with recursion

```rust
fn compare_packets(left: &Value, right: &Value) -> Ordering {
    match (left, right) {
        // Both numbers: direct comparison
        (Value::Number(l), Value::Number(r)) => {
            l.as_i64().unwrap().cmp(&r.as_i64().unwrap())
        }

        // Both arrays: element-by-element with length tiebreaker
        (Value::Array(l_arr), Value::Array(r_arr)) => {
            for i in 0..l_arr.len().min(r_arr.len()) {
                match compare_packets(&l_arr[i], &r_arr[i]) {
                    Ordering::Equal => continue,
                    other => return other,  // First mismatch determines order
                }
            }
            l_arr.len().cmp(&r_arr.len())  // Shorter wins
        }

        // Mixed: Convert number to [number] and recurse
        (Value::Number(_), Value::Array(_)) => {
            let l_arr = Value::Array(vec![left.clone()]);
            compare_packets(&l_arr, right)
        }

        (Value::Array(_), Value::Number(_)) => {
            let r_arr = Value::Array(vec![right.clone()]);
            compare_packets(left, &r_arr)
        }

        _ => Ordering::Equal,
    }
}
```

**Key insights**:
- **Pattern matching** cleanly handles all 4 cases
- **Recursion** handles arbitrary nesting depth
- **Early return** on first mismatch for efficiency
- **Type coercion** isolated to 2 cases (number → [number])

**Example trace**:
```
compare([[1],[2,3,4]], [[1],4])
├─ Both arrays, compare elements
├─ [0]: compare([1], [1])
│  └─ Both arrays: [0] = 1 == 1, length equal → Equal
├─ [1]: compare([2,3,4], 4)
│  ├─ Mixed! Convert right to [4]
│  └─ compare([2,3,4], [4])
│     └─ Both arrays: [0] = 2 < 4 → Less ✅
```

**Part 1 result**: 5852 (sum of correctly ordered pair indices)

### Part 2: Sorting with Divider Packets

**Algorithm**: Collect, add dividers, sort, find

```rust
fn solve_part2_with_data(data: &ParsedData) -> usize {
    // Collect all packets from pairs
    let mut packets: Vec<Value> = data.pairs
        .iter()
        .flat_map(|pair| vec![pair.left.clone(), pair.right.clone()])
        .collect();

    // Add divider packets
    let divider1 = serde_json::from_str("[[2]]").unwrap();
    let divider2 = serde_json::from_str("[[6]]").unwrap();
    packets.push(divider1.clone());
    packets.push(divider2.clone());

    // Sort using our comparison function
    packets.sort_by(compare_packets);

    // Find divider positions (1-based)
    let mut idx1 = 0;
    let mut idx2 = 0;
    for (idx, packet) in packets.iter().enumerate() {
        if packet == &divider1 { idx1 = idx + 1; }
        else if packet == &divider2 { idx2 = idx + 1; }
    }

    idx1 * idx2
}
```

**Key insights**:
- **flat_map()** flattens pairs into individual packets
- **sort_by()** reuses our `compare_packets` function!
- **Linear search** to find dividers (simple and correct)
- **Product of indices** is the decoder key

**Part 2 result**: 24190 (decoder key)

**Pattern learned**:

### 3. Recursive Functions Need Clear Structure

**compare_packets function structure**:
- **Base case**: Both numbers (no recursion)
- **Recursive case 1**: Both arrays (recurse on elements)
- **Recursive case 2**: Mixed types (convert, then recurse)

**Critical**: Every recursive call makes problem **smaller**:
- Array comparison: Recurse on subarray (fewer elements)
- Type coercion: Recurse after conversion (simpler types)

**Proof of termination**:
- Eventually reach numbers (base case)
- Or array becomes empty (length comparison)

**Lesson**: Design recursive functions with **clear base case first**, then recursive cases that make progress toward it.

**Problem uses 1-based**: "The first pair has index 1"

**Solution**: Convert at boundaries

### 6. Early Return Optimizes Element-by-Element Comparison

**Naive approach** (compare all, then decide):
```rust
let mut all_equal = true;
for i in 0..min_len {
    if left[i] != right[i] {
        all_equal = false;
    }
}
```

**Optimized approach** (return on first mismatch):
```rust
for i in 0..min_len {
    match compare(&left[i], &right[i]) {
        Ordering::Equal => continue,
        other => return other,  // ← Early return!
    }
}
```

**Performance difference**:
- Naive: Always O(n) comparisons
- Optimized: O(k) where k = position of first mismatch (often << n)

**Lesson**: In comparison algorithms, **first mismatch determines order** - return immediately!

## 📚 Mathematical Concepts Applied

### Order Theory

**Lexicographic Order**: Ordering sequences by comparing elements position-by-position

**Properties**:
- **Transitive**: If A < B and B < C, then A < C
- **Antisymmetric**: If A < B, then not B < A
- **Total**: For any A, B either A < B, A == B, or A > B

**Example**:
```
[1,1,3] < [1,1,5]  (3 < 5 at position 2)
[1,1,3] < [1,1,3,1,1]  (shorter wins when prefix matches)
```

**Application**: Sorting algorithms rely on total order

---

### Type Coercion

**Concept**: Converting values to compatible types for comparison

**Rules in this problem**:
- Integer `n` → Array `[n]`
- Then compare as arrays

**Mathematical view**: 
- Integers are **embedded** in the space of arrays (singletons)
- Comparison is **well-defined** on the union of types

**This is category theory** (morphisms between types), but we don't need the theory to implement it!

---

### Recursion Theory

**Structural Recursion**: Recursion following data structure

**Data structure**: Nested lists (tree structure)
```
      [·,·,·]
     /   |   \
    1   [·,·]  3
        /   \
       2    [·]
            |
            4
```

**Recursive comparison**: Compare at each node
- **Leaves** (numbers): Base case
- **Branches** (arrays): Recursive case

**Termination**: Tree depth is finite, recursion always reaches leaves

---

### Complexity Analysis

**Part 1 complexity**: O(n × m × d)
- n = number of pairs
- m = average elements per packet
- d = average nesting depth

**Part 2 complexity**: O(n log n × m × d)
- Sorting dominates (n log n comparisons)
- Each comparison is O(m × d)

**Actual performance**: 721µs for n=150, m≈5, d≈3 (very manageable)
