## 🔧 **Technical Insights**

### **Function Pointers**
- Function pointers have fixed size (8 bytes on 64-bit), unlike closures
- Cannot capture environment - purely stateless
- Enum variant constructors work as function pointers: `(0..5).map(Status::Value)`
- Use `fn` for simple callbacks, `Fn` traits for closures with captures

### **Macros**
- **Declarative** (`macro_rules!`): Pattern matching on code structure
  - Repetition: `$(...)*` (zero+), `$(...)+` (one+), `$(...)?` (optional)
  - Pattern designators: `ident`, `expr`, `ty`, `stmt`, `block`, etc.
- **Procedural**: Token stream processing with full Rust code
  - Derive macros: Auto-implement traits (`#[derive(Debug)]`)
  - Attribute macros: Custom attributes on items (`#[route(GET, "/")]`)
  - Function-like: Look like functions but operate on tokens (`sql!(...)`)
- Zero-cost abstraction - all expansion happens at compile time

### **Rayon Data Parallelism**
- **Parallel overhead is real**: Thread spawning costs ~100µs
- **Optimal use cases**: Large datasets (>10k items) OR expensive per-item work
- **Ergonomic API**: Just add `par_` prefix to iterator methods
- **Type safety**: Compiler enforces `Send + Sync` traits preventing data races
- **Work stealing**: Automatic load balancing across CPU cores
- **Tuple reduction pattern**: Elegant multi-counter aggregation in parallel
- **Educational value**: Performance measurement shows exactly when parallel helps

### **Modular Arithmetic**
- **`rem_euclid()` vs `%`**: Critical for wraparound with negative numbers
  - Example: `-3 % 101 = -3` ❌ vs `-3.rem_euclid(101) = 98` ✅
  - Essential for grid simulation with negative velocities
- **Pattern detection**: Finding configurations via constraint satisfaction (uniqueness check)
