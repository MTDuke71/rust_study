## Day 21: Monkey Math

**Problem**: ~2,800 monkeys form a binary expression tree. Part 1: evaluate `root`. Part 2: `root` becomes equality check, find what `humn` must yell.

### Results
- **Part 1**: 160,274,622,817,992 (recursive tree evaluation) - 32µs
- **Part 2**: 3,087,390,115,721 (algebraic inversion walk) - 217µs
- **Combined**: ~499µs

### Algorithm: Recursive Evaluation + Inversion Walk

**Part 1**: Recursive DFS evaluation — each monkey resolves by evaluating dependencies depth-first. No memoization needed because the structure is a tree (each node visited exactly once).

**Part 2**: Algebraic inversion — determine which branch of `root` contains `humn`, evaluate the other branch for the target, walk toward `humn` inverting operations at each level.

**Non-commutative trap**: `k - x = t` means `x = k - t` (NOT `t - k`). Same for division.

## Day 22: Monkey Map

**Problem**: Navigate a sparse 2D board with wrapping. Part 1: flat wrap to opposite edge. Part 2: cube-fold the board and wrap to adjacent cube face.

### Results
- **Part 1**: 88,226 (flat wrapping walk) - 318µs
- **Part 2**: 57,305 (cube wrapping walk) - 327µs
- **Combined**: ~1.46ms

### Algorithm: HashMap Board + Hardcoded Cube Transitions

**Parsing**: `HashMap<(row, col), Tile>` for sparse non-rectangular board (rows start at different columns). Row/column range maps for O(1) flat wrapping lookup.

**Part 1**: Follow path instructions (Move N steps, Turn L/R). When stepping off-map, wrap to opposite edge of same row/column using range maps.

**Part 2**: Same walk, but when stepping off a face edge, use `cube_wrap()` — a match on the out-of-bounds `(row, col, facing)` tuple that maps to 14 non-adjacent edge transitions. Adjacent faces (1↔2, 1↔3, etc.) use natural steps.

### Design Decision: HashMap vs Mission 6 Grid

Mission 6's `Grid<T>` requires rectangular dimensions and panics on unequal row lengths. Day 22's board is sparse (rows start at col 0 or col 50 with different widths), making HashMap the better choice. The row/column range tracking enables O(1) wrapping lookups.

### Cube Net Layout (Actual Input)
```
  ┌───┬───┐
  │ 1 │ 2 │     rows   0- 49
  ├───┼───┘
  │ 3 │           rows  50- 99

│ 4 │ 5 │         rows 100-149
├───┼───┘
│ 6 │              rows 150-199
└───┘
```

14 non-adjacent edge transitions hardcoded as match arms. Each uses the out-of-bounds coordinate as a unique dispatch key.

## Patterns Worth Remembering

- **HashMap for sparse boards**: When the grid is non-rectangular or has significant empty regions, HashMap<(row,col), Tile> beats a rectangular grid
- **Range maps for wrapping**: Precompute per-row and per-col min/max to enable O(1) wrap-to-opposite-edge
- **Out-of-bounds as dispatch key**: Stepping one past an edge produces unique coordinates that identify which face transition to apply — clean match-based dispatch
- **Hardcoded > general for AoC**: 14 match arms are clearer and faster than a general cube-folding algorithm
- **`char_indices()` over `chars().enumerate()`**: Clippy enforces this to avoid char/byte index confusion in string slicing
