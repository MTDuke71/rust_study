**Problem**: Map seeds through 7-stage transformation pipeline (seed→soil→fertilizer→water→light→temperature→humidity→location), find minimum location.

**Part 1**: Individual seed mapping → **379,811,651**
- 20 seeds through 7 transformation stages
- Range mapping with O(1) lookup or passthrough
- Runtime: **34.6µs** (Criterion benchmark)

**Part 2**: Seeds as range pairs (650M values!) → **27,992,443**  
- Challenge: 650 million individual seeds - can't iterate them all
- Solution: **Range intersection and splitting** - work with ranges throughout
- 10 input ranges → ~30 final ranges after 7 stages
- Runtime: **783.8µs** (23× slower than Part 1, but handles 32M× more data!)

**Key Algorithm: Range Intersection/Splitting**
```rust
// Range [50..70) through rule [55..65) → [100..110)
// Splits into 3 parts:
//   [50..55)   - unmapped before
//   [100..110) - mapped intersection  
//   [65..70)   - unmapped after

    -> (Option<Range>, Vec<Range>)
```

- **AoC 2023 Progress**: 5/25 days ⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐ (total runtime: 1.899ms): Iterate all 650M values × 7 stages = 4.55 billion operations → Hours
**Optimized Approach**: Compress to ranges, split/merge through transformations → <1ms

**Key Technique**: Range intersection with three-way split
- Intersection with mapping rule → transformed range (mapped)
- Before intersection → unchanged (unmapped, continue processing)
- After intersection → unchanged (unmapped, continue processing)

**Rust Implementation Patterns**:
```rust
// Return type captures both mapped and unmapped portions
fn map_range_through_rule(range: Range, rule: &RangeMap) 
    -> (Option<Range>, Vec<Range>)

// Process unmapped parts through remaining rules
let mut to_process = vec![range];
for rule in rules {
    let mut next = Vec::new();
    for r in to_process {
        let (mapped, unmapped) = map_through_rule(r, rule);
        if let Some(m) = mapped { results.push(m); }
        next.extend(unmapped);
    }
    to_process = next;
}
```

**Trade-offs**:
- Range manipulation has overhead (Part 2: 783µs vs Part 1: 34µs)
- But enables solving problems that would be computationally infeasible
- Essential pattern for interval/range transformation problems
