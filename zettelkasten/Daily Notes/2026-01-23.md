## 🔧 **Technical Insights**

### Graph Contraction Technique
- **Problem**: Longest path is NP-hard (exponential complexity)
- **Naive approach**: DFS on 20K tiles caused stack overflow (7,000 depth)
- **Solution**: Identify junctions (degree ≠ 2), collapse corridors into weighted edges
- **Result**: 35 junctions vs 20,000 tiles, recursion depth 35 vs 7,000
- **Learning**: State space reduction via preprocessing can transform impossible → solvable

### Backtracking Pattern (HashSet)
- Use `HashSet<Coord>` for visited tracking (O(1) operations)
- Critical: `visited.remove(&coord)` after recursion (backtrack!)
- Pattern: Make choice → Recurse → Undo choice
- Explores all possible paths while preventing cycles

### ✅ Rust for Rustaceans Ch4 - Error Propagation Deep Dive (COMPLETE)

**Achievement**: Comprehensive understanding of Rust's error handling philosophy and practical patterns

**Key Concepts Mastered**:

1. **From and Into Traits** - Type conversion for error handling
   - **Golden Rule**: "Implement `From`, use `Into`"
   - `From` superior for explicit calls: `MyType::from(value)`
   - `Into` superior for trait bounds: `fn foo(arg: impl Into<MyType>)`
   - **`?` operator uses `From`** (not `Into`) - older libraries with only `Into` won't work with `?`
   - Standard library provides blanket impl: `impl<T, U> Into<U> for T where U: From<T>`

2. **Errors are Values, Not Exceptions** - The Rust Philosophy
   - Errors explicit in function signatures: `Result<T, E>`
   - No hidden control flow or stack unwinding
   - Compiler enforces handling (won't compile if ignored)
   - Zero-cost abstractions (as fast as C error codes)

3. **Why Rust is More Robust than Python's try/except**:
   - **No surprises**: Signatures show what can fail
   - **Compile-time enforcement**: Forgot to handle? Won't compile
   - **Visible control flow**: `?` shows early returns explicitly
   - **Exhaustive handling**: Must handle all error variants
   - **Performance**: No exception overhead, simple enum branching

4. **Seven Error Propagation Patterns** (error_propagation.rs example):
   - **Pattern 1**: `?` operator - basic early return
   - **Pattern 2**: `From` trait - automatic error type conversion
   - **Pattern 3**: Error chains with context - preserve causality
   - **Pattern 4**: `map_err` - transform errors inline
   - **Pattern 5**: `and_then` chaining - functional composition
   - **Pattern 6**: Extension traits - custom helper utilities
   - **Pattern 7**: Error chain traversal - debugging & diagnostics

**Rust vs Python Error Handling**:

```python
# Python: Hidden failures, runtime crashes
def process(file):
    data = open(file).read()    # Can throw FileNotFoundError
    return parse(data)          # Can throw ValueError
# Easy to forget error handling → production crashes
```

```rust
// Rust: Explicit failures, compile-time safety
fn process(file: &str) -> Result<Data, MyError> {
    let data = fs::read_to_string(file)?;  // ← Visible early return
    parse(&data)?                           // ← Visible early return
}
// MUST handle Result or code won't compile
```

**Critical Insights**:
- **Try trait (unstable)**: NOT like Python's try/except - it's an abstraction for `?` operator
  - Python try/except: Catches runtime exceptions (non-local jumps)
  - Rust Try trait: Powers early returns with explicit values (local control flow)
  - Rust has NO exceptions - all errors are explicit `Result` values
- **Type conversions**: `as` for primitives (can lose data), `From`/`Into` for type-safe conversions
- **Multiple propagation patterns**: Different situations need different tools
  - Prototype: `?` + `Box<dyn Error>`
  - Library: Custom error types with `From` impls
  - Application: `map_err` for user messages
  - Production: Error chains with full context
