### Rust for Rustaceans Ch3: Obvious Interfaces

Read Ch3 "Obvious" section (pp. 47-48) - confirms and codifies practices already in use.

**Key Takeaways**:

1. **Documentation is Critical**:
   - Document panics, errors, and safety requirements (already doing in missions)
   - Include usage examples in doc comments (mission READMEs have "Complete Runnable Example")
   - Use `#[doc(cfg(...))]` for feature-gated APIs
   - Use `#[doc(alias = "...")]` for discoverability (e.g., alias "push_back" → "push")

2. **Semantic Types Over Primitives**:
   - `Port(u16)` is better than raw `u16` - self-documenting
   - Type system enforces domain constraints at compile time
   - Already applied: Mission types like `Coord`, `Grid<T>`, not raw tuples

3. **Type-State Pattern**:
   - Encode state machine in types: `Connection<Disconnected>` vs `Connection<Connected>`
   - Operations only available in valid states (compile-time safety)
   - `.send()` only exists for `Connection<Connected>` - prevents logic errors

4. **`#[must_use]` Annotation**:
   - Prevents accidentally ignoring `Result`, builders, or other critical returns
   - Compiler warning if return value not used
   - Already using via `anyhow::Result` in AoC solutions

**Reflection**: These are patterns we've been following organically (doc examples, semantic types in missions, Result handling). RfR formalizes *why* they work - they make interfaces "obvious" by encoding invariants in the type system and documentation, not just runtime checks.

**Connection to Day 15**: Hash function returns `u8` not `usize` - semantic typing! Documents 0-255 constraint via type.

### Mission 11: REQ-4 Boolean → Counting DP Transformation ✅

Implemented comprehensive demo of the canonical transformation pattern:

**REQ-4 Implementation**:
- Created `demo_counting_paths.rs` (320 lines) - Side-by-side boolean vs counting DP
- Pattern matching example: "ab" has 2 ways, "aba" has 3 ways, "abab" has 5 ways
- Climbing stairs example: 10 stairs = 89 ways (Fibonacci progression)
- Cache statistics demo: 8 'a's with patterns ["a", "aa", "aaa"] = 81 ways, only 8 subproblems cached

**Key Insight - Identical Structure**:
```rust
// Boolean: Early-exit OR logic
if can_build(remainder, patterns, memo) {
    return true;  // ← Stop on first success
}

// Counting: Accumulative SUM logic  
total += count_ways(remainder, patterns, memo);  // ← Sum all paths
```

**Only 3 Changes**:
1. Return type: `bool` → `u64`
2. Base case value: `true` → `1`
3. Reduction operator: OR (early-exit) → SUM (accumulate)

**Performance Demo**:
- "aaaaaaaa" (8 'a's) with patterns ["a", "aa"]: 34 distinct ways
- Memoized: 4.6µs with 8 cache entries
- Naive theoretical: O(2^8) = 256 recursive calls without memoization
