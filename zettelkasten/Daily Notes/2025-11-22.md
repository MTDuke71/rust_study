#### 1. Rust Book Chapter 17.3 - Async Performance Investigation

**Windows Timer Resolution Discovery** - Critical performance insight for async/await

- **Created `17_3_book.rs`** - Windows-specific performance analysis example
  - Demonstrated ~15.6ms minimum sleep time on Windows by default
  - Showed 10× improvement to ~1-2ms with `timeBeginPeriod(1)`
  - Explained why Listing 17-14's "100 futures" example took 1.45 seconds instead of 100ms
  - **Key Finding**: Windows timer granularity is the bottleneck, not Rust/tokio overhead

**Technical Deep Dive**:
```rust
// Without timeBeginPeriod: ~15.6ms minimum per trpl::sleep(1ms)
// With timeBeginPeriod(1): ~1-2ms actual sleep time
// 100 iterations × 15.6ms = 1560ms (matches Book's observed 1.45s)
```

**OS Architecture Insight**:
- Windows default timer resolution: 15.625ms (system tick rate)
- Even `sleep(1ms)` rounds up to next timer tick
- `timeBeginPeriod(1)` requests higher resolution globally (affects entire system)
- Must call `timeEndPeriod(1)` to restore (or Windows does on process exit)

**Key Concepts**:
- **Streams = async iterators** - `next().await` returns `Option<Item>`
- **Backpressure-aware** - Consumer controls pace via `.await`
- **Composable** - Filter, map, merge, throttle chain together
- **Lazy evaluation** - Only processes when pulled by consumer

**Stream vs Channel Distinction**:
```rust
// Channel: push-based (sender controls rate)
tx.send(value).await;

// Stream: pull-based (receiver controls rate)
while let Some(value) = stream.next().await { }
```

#### 5. Math-Based Optimization - Learning from Python

**Python Solution Comparison** revealed better approach:
- Python used `floor(log(stone, 10)) + 1` for digit counting
- No string conversion overhead
- Inspired Rust refactoring

**Refactored from String-Based to Math-Based**:

**Before (String Operations)**:
```rust
let num_str = stone.to_string();           // Heap allocation
let num_digits = num_str.len();
let left = num_str[..mid].parse::<u64>().unwrap();  // String parsing
let right = num_str[mid..].parse::<u64>().unwrap();
```

**After (Integer Arithmetic)**:
```rust
fn count_digits(n: u64) -> u32 {
    if n == 0 { return 1; }
    (n as f64).log10().floor() as u32 + 1  // Math-based counting
}

let divisor = 10_u64.pow(num_digits / 2);
let left = stone / divisor;     // Integer division
let right = stone % divisor;    // Modulo for remainder
```

**Performance Benefits**:
- Eliminated heap allocations (no `String` creation)
- Removed string parsing overhead
- Pure integer arithmetic (faster CPU operations)
- More elegant - treats numbers as numbers!

**Mathematical Principles**:
- **Digit counting**: `floor(log10(n)) + 1 = digit_count`
  - 1234: log10(1234) = 3.09... → floor = 3 → 3+1 = 4 digits ✓
- **Splitting**: For 1234 (4 digits) split at position 2:
  - Divisor: 10^2 = 100
  - Left: 1234 / 100 = 12 (integer division)
  - Right: 1234 % 100 = 34 (modulo remainder)

#### Async Streams Architecture

| Concept | Description | Example |
|---------|-------------|---------|
| **ReceiverStream** | Wraps channel receiver as stream | `ReceiverStream::new(rx)` |
| **Backpressure** | Consumer controls rate via `.await` | Stream only advances when pulled |
| **Adapters** | Transform stream items | `.filter()`, `.map()`, `.throttle()` |
| **Merging** | Combine multiple streams | `merge(stream1, stream2)` |
| **Batching** | Group items into windows | Process chunks instead of individuals |

#### Memoization Design Patterns

| Aspect | Day 11 Implementation | General Pattern |
|--------|----------------------|-----------------|
| **Cache Key** | `(stone_value, blinks_remaining)` | All state variables that affect result |
| **Cache Type** | `HashMap<(u64, usize), usize>` | Map from inputs to computed result |
| **Lookup Strategy** | Check cache first, compute if miss | Top-down recursive with cache |
| **Efficiency Metric** | 130K entries for 223T states | Cache size << theoretical state space |

#### Math vs String Trade-offs

| Operation | String Approach | Math Approach | Winner |
|-----------|----------------|---------------|--------|
| **Digit Counting** | `to_string().len()` | `log10().floor() + 1` | **Math** (no allocation) |
| **Splitting** | String slicing + parse | Integer division + modulo | **Math** (faster arithmetic) |
| **Readability** | Obvious what it does | Requires math knowledge | String (but comments help) |
| **Performance** | Heap allocation overhead | Stack-only operations | **Math** (10-100× faster) |

- **AUTOSAR**: Sender-Receiver communication with queues

- **AUTOSAR**: Caching computed diagnostic values to avoid recalculation
- **Rust Memoization**: HashMap storing subproblem results
- **Key Similarity**: Trade memory for computation time
