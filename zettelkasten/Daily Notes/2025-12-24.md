## 🔧 **Technical Insights**

### Windows Line Ending Bug Fix
- **Problem**: `split("\n\n")` only found 1 schematic instead of 500 on Windows
- **Root Cause**: Windows `\r\n` line endings vs Unix `\n` - blank line became `\r\n\r\n`
- **Solution**: `.replace("\r\n", "\n")` normalization before splitting
- **Impact**: Transformed complete failure → correct answer (0 → 3508 compatible pairs)
- **Pattern**: Always normalize line endings for cross-platform file parsing

### Direction-Aware Scanning Pattern
- **Locks**: Scan downward from row 1, count '#' until hitting '.'
- **Keys**: Scan upward from bottom-1, count '#' until hitting '.'
- **Benefit**: Early-exit scanning more explicit than universal counting
- **Type Safety**: Separate `Lock` and `Key` structs prevent accidental confusion

### Iterator Chain Validation
```rust
self.heights.iter()
    .zip(key.heights.iter())
    .all(|(lock_h, key_h)| lock_h + key_h <= max_height)
```
- Three-step process: iterate → pair → validate with short-circuit
- Zero allocations, functional approach
- O(1) memory vs building intermediate collections
