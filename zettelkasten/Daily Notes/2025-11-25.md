### Phase 3: Implementation - Part 2 (Corner Counting Algorithm)

**Geometric Insight**: The number of sides equals the number of corners for any polygon (including polygons with holes).

**Algorithm Design**:
```rust
fn count_sides(region_coords: &[Coord]) -> usize {
    let region_set: HashSet<_> = region_coords.iter().copied().collect();
    let mut corners = 0;

    for &coord in region_coords {
        // Check 4 corner positions around each cell:
        // Top-left, top-right, bottom-left, bottom-right

        // For each corner, detect:
        // 1. Outer corner (convex): !North && !West
        // 2. Inner corner (concave): North && West && !NorthWest
    }

    corners
}
```

**Corner Detection Logic**:
- **Outer Corner (Convex)**: Neither orthogonal neighbor exists
  - Example: Top-left corner when `!North && !West`
  - Region "sticks out" at this corner
- **Inner Corner (Concave)**: Both orthogonal neighbors exist but diagonal is missing
  - Example: Top-left when `North && West && !NorthWest`
  - Region "caves in" at this corner

**Why This Works**:
- Fundamental polygon property: Every polygon has equal number of sides and corners
- Works for any shape: rectangles, L-shapes, E-shapes, nested regions with holes
- Eliminates need for complex edge tracing or grid rotation algorithms

**Code Structure**:
```rust

    F: Fn(usize, usize, &[Coord]) -> usize,
{
    // Single flood fill loop implementation
    // Accepts closure for cost calculation
}

// Part 1: One-liner
fn calculate_total_fencing_cost(grid: &Grid<char>) -> usize {
    calculate_total_cost(grid, |area, perimeter, _coords| area * perimeter)
}

// Part 2: One-liner
fn calculate_total_bulk_discount_cost(grid: &Grid<char>) -> usize {
    calculate_total_cost(grid, |area, _perimeter, coords| {
        let sides = count_sides(coords);
        area * sides
    })
}
```

**Benefits**:
- **Code Reduction**: Eliminated ~30 lines of duplicate code
- **DRY Principle**: Single source of truth for region scanning algorithm
- **Functional Pattern**: Demonstrates closures for algorithm family variations
- **Type Safety**: Generic bounds ensure correct closure signature
- **Maintainability**: Changes to flood fill logic only needed in one place

### Corner Counting Algorithm Analysis

**Mathematical Foundation**:
- **Euler's Formula for Polygons**: For any simple polygon, V - E + F = 2
- **Corners = Vertices**: Each corner is a vertex where polygon direction changes
- **Sides = Edges**: Each straight section between vertices is a side
- **Property**: For polygons (including those with holes), # of corners = # of sides

**Algorithm Correctness**:
- **Outer corners**: Detected when region "sticks out"
  - Condition: Neither orthogonal neighbor exists
  - Example: Top-left when !N && !W
- **Inner corners**: Detected when region "caves in"
  - Condition: Both orthogonal neighbors exist, diagonal doesn't
  - Example: Top-left when N && W && !NW
- **Complete coverage**: Checking all 4 corners per cell ensures no corner missed
- **Handles holes**: Inner corners naturally counted for regions with interior gaps

**Comparison with Python Approach**:

**Python Algorithm** (String Manipulation + Rotation):
1. Create padded grid (border of spaces around region)
2. Scan horizontally: Find positions where current row differs from row above
3. Build string of 'X' or ' ' representing edge transitions
4. Count contiguous segments using `split()` trick
5. Rotate grid 90° and repeat for vertical edges

**Rust Algorithm** (Corner Counting):
1. Convert region coordinates to HashSet for O(1) lookups
2. For each cell, check 4 corner positions
3. Count outer corners (!N && !W pattern)
4. Count inner corners (N && W && !NW pattern)
5. Return total corners (= sides)

**Comparison**:
- **Memory**: Python allocates padded grid + rotated grid vs Rust's single HashSet
- **Allocations**: Python uses string building vs Rust's in-place counting
- **Clarity**: Python's rotation trick is clever but indirect; Rust's corner counting is direct
- **Scalability**: Rust approach O(R) with 8 checks/cell; Python O(R) with string operations
- **Correctness**: Both work, but Rust's mathematical approach is more explicit
