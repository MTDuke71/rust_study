### Implementation Highlights
**Lookup Tables - The Core Innovation**:
```rust
const PART1_SCORES: [[u8; 3]; 3] = [
    [1+3, 2+6, 3],  // Opponent Rock: you Rock/Paper/Scissors
    [1, 2+3, 3+6],  // Opponent Paper

];

// Zero branches: SCORES[opponent][your_move]
```

**Byte Manipulation for Speed**:
```rust
let opponent = bytes[0].wrapping_sub(b'A');  // A→0, B→1, C→2
let you = bytes[2].wrapping_sub(b'X');       // X→0, Y→1, Z→2
```

**Key Advantages**:
1. ✅ **Branchless** - No `if`/`match` statements (prevents branch mispredictions)
2. ✅ **Cache-friendly** - 18 bytes total fits in single L1 cache line
3. ✅ **Compact data** - 2 bytes/round vs 8+ with enums
4. ✅ **Direct indexing** - O(1) lookup per round

## 🔧 **Technical Insights**

### Lookup Table Pattern - When to Use
✅ **Good fit**:
- Small, enumerable input space (≤100 possibilities)
- Deterministic mappings (pure functions)
- Performance-critical inner loops
- ASCII input with consecutive characters

❌ **Poor fit**:
- Large input spaces (>1000 possibilities)
- Complex, context-dependent logic
- Unicode handling required

### Performance Deep Dive
**Parsing dominates** (19.9µs = 92.6% of runtime):
- String→bytes conversion
- Vec allocation
- Iterator overhead

**Scoring is nearly free** (1.6µs for 5000 lookups):
- 0.32ns per lookup (both parts)
- Demonstrates power of branch elimination
- Cache hits on tiny lookup table

**Optimization ceiling reached**:
- SIMD parsing: ~50% parsing improvement (high complexity)
- Inline sum: ~7% total improvement (hurts readability)
- Verdict: Current implementation **already near-optimal**

### Rust Techniques Demonstrated
- `as_bytes()` for raw byte access (faster than char iteration)
- `wrapping_sub` for safe arithmetic (no panics on invalid input)
- `const` arrays for compile-time lookup tables
- `filter_map` for optional parsing results
- Direct byte indexing: `bytes[0]` and `bytes[2]`

### Mathematical Foundation
**Rock-Paper-Scissors as Cyclic Group**:
- Mod 3 arithmetic: `(you - opp) % 3` determines outcome
- `diff == 0` → draw (score 3)
- `diff == 1` → win (score 6)
- `diff == 2` → lose (score 0)

Alternative implementation using modular arithmetic:
```rust
let outcome = match (you + 3 - opp) % 3 {
    0 => 3, 1 => 6, 2 => 0,
    _ => unreachable!(),
};
```

**Trade-off**: More generalizable (scales to N-way games) but slightly slower and less obvious.
