## 🔧 **Technical Insights**

### Custom Ord Pattern - Multi-Level Sorting
**Discovery**: Implementing `Ord` with multiple comparison levels is cleaner than custom comparators

```rust
impl Ord for Hand {
    fn cmp(&self, other: &Self) -> Ordering {
        match self.hand_type.cmp(&other.hand_type) {
            Ordering::Equal => {
                // Tiebreaker: compare cards left-to-right
                for i in 0..5 {
                    match self.cards[i].cmp(&other.cards[i]) {
                        Ordering::Equal => continue,
                        other => return other,
                    }
                }
                Ordering::Equal
            }
            other => other,
        }
    }
}
```

**Benefits**:
- Enables automatic `.sort()` usage
- Type-safe comparison (compiler prevents mixing incompatible types)
- Self-documenting (comparison logic in one place)
- Early termination (stops at first difference)

### Frequency Analysis for Hand Types
**Insight**: Hand type determined by frequency pattern, not specific cards

```rust
// Which cards appear how many times?
HashMap → [4, 1] → Four of a kind (4 of one card, 1 of another)
HashMap → [3, 2] → Full house (3 of one, 2 of another)
HashMap → [2, 2, 1] → Two pair (2 of one, 2 of another, 1 different)
```

**Why this works**: Poker hand strength depends on patterns, not identities
- Don't care *which* card appears 4 times
- Just that *some* card appears 4 times

### Greedy Joker Assignment is Optimal
**Theorem**: To maximize hand strength, add all jokers to the most frequent card

**Proof**: Hand strength increases with largest frequency. Adding K jokers to frequency N gives (N+K). To maximize result, maximize N before adding jokers.

**Example**:
```
Hand: [Q, Q, J, J, 2]
Option 1: Add Js to Q (freq=2) → [4, 1] = Four of a kind ✓
Option 2: Add Js to 2 (freq=1) → [2, 3] = Full house ✗
Option 3: Split Js → [3, 2] = Full house ✗
```

### Type-Driven Design Prevents Bugs
**Pattern**: Use separate types for Part 1 and Part 2 instead of flags/enums

```rust
// ✅ Compile-time safety
struct Hand { cards: [Card; 5], ... }
struct Hand2 { cards: [Card2; 5], ... }
// Can't accidentally compare Hand with Hand2 - won't compile!

// ❌ Runtime checking required
struct Hand { cards: Vec<Card>, part: Part }
// Must check part == other.part at runtime
```

**Tradeoff**: Slight code duplication vs guaranteed correctness
