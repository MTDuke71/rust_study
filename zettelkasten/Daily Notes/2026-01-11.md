## 🔧 **Technical Insights**

### Dynamic Programming Strategy Selection

**When Tabulation (Bottom-Up) Beats Memoization:**
- **Dense solution spaces**: Need most/all subproblems (coin change with [1,5,10,25])
- **Simple iteration order**: Clear dependencies (Fibonacci i → i-1, i-2)
- **Performance critical**: 5-20x faster in practice due to:
  - No recursion overhead
  - O(1) array indexing vs O(log n) HashMap lookup
  - Better CPU cache locality (sequential memory)

**When Memoization (Top-Down) Wins:**
- **Sparse solution spaces**: coins=[500,1000], amount=1000 (only 3 subproblems!)
- **Complex dependencies**: Hard to determine iteration order
- **Early termination**: Can stop before solving everything
- **Natural recursion**: Problem structure maps to recursive thinking

### Complexity Analysis Learned

| **Approach** | **Time** | **Space** | **Practical Speed** |
|--------------|----------|-----------|---------------------|
| Naive Recursion | O(m^n) | O(n) stack | Exponential - unusable for n>50 |
| Memoization | O(m×n) | O(n) memo+stack | Good - HashMap overhead |
| Tabulation | O(m×n) | O(n) array | Best - minimal overhead |
| Bounded Binary | O(n×Σlog(k)) | O(n) | Efficient for quantity limits |

**Real Results** (amount=50, coins=[1,5,10,25]):
- Naive: 104ms ❌
- Memoized: 35.2µs ✓
- Bottom-up: 7.8µs ✅ (4.5x faster!)

### Helper Function Pattern in DP

Memoization requires **two-function pattern**:
```rust
// Wrapper: Initializes cache once
fn min_coins_memoized(coins: &[u32], amount: u32) -> Option<u32> {
    let mut memo = HashMap::new();
    min_coins_memo_helper(coins, amount, &mut memo)
}

// Helper: Does recursion, shares cache across calls
fn min_coins_memo_helper(coins: &[u32], amount: u32, memo: &mut HashMap<u32, Option<u32>>) -> Option<u32> {
    // Cache lookup, recursion, cache storage
}
```
**Why?** Can't initialize HashMap inside recursive function - would create new cache on each call!
