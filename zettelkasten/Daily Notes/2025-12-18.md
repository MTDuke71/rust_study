### Bidirectional Search Optimization

Key insight: **Exponential reduction** in nodes explored when searching from both ends
- Single-directional: $10^6$ nodes at depth 6, branching factor 10
- Bidirectional: $2 \times 10^3 = 2,000$ nodes (500x faster!)
- Critical for large graphs with known start and goal nodes

### Day 19 - Pattern Matching with Dynamic Programming

**Problem**: Determine which towel designs can be made and count all possible arrangements

**Approach**: Memoized recursion
```rust
fn count_ways_recursive(patterns: &[&str], remaining: &str, memo: &mut HashMap) -> u64 {
    if remaining.is_empty() { return 1; }  // Base case
    if let Some(&count) = memo.get(remaining) { return count; }
    
    let total = patterns.iter()
        .filter_map(|p| remaining.strip_prefix(p))
        .map(|rest| count_ways_recursive(patterns, rest, memo))
        .sum();
    
    memo.insert(remaining, total);
    total
}
```

**Key Insights**:
- Each design is independent - perfect for parallel processing
- Memoization essential - prevents exponential recalculation
- Pattern prefix matching with `strip_prefix` is elegant
- Part 2 extends Part 1 by counting instead of checking boolean
