### AoC 2023 Day 1: Trebuchet?! ⭐⭐

**Problem**: Extract calibration values from text - first/last digits per line, sum all values.
- **Part 1**: Numeric digits only → **54239**
- **Part 2**: Digits can be spelled out (one, two, etc.) → **55343**

**Key Implementation Pattern**: Forward/Reverse Search with Early Termination
```rust
// Part 1: Char-based search
let first = line.chars().find_map(|c| c.to_digit(10))?;
let last = line.chars().rev().find_map(|c| c.to_digit(10))?;

// Part 2: Position-based search (words look forward from each position)
let first = (0..line.len()).find_map(|pos| digit_at_position(line, pos))?;
let last = (0..line.len()).rev().find_map(|pos| digit_at_position(line, pos))?;
```

**Performance** (measured, release mode, 100 iterations):

| Part | Time |
|------|------|
| Part 1 | 28µs |
| Part 2 | 38µs |
| **Total** | **66µs** |

**Rust Insights**:
- `find_map` is perfect for "find first match and transform" - early termination built-in
- `.rev()` on range `(0..n)` iterates positions backward while check function still looks forward
- Overlapping word digits (e.g., `"sevenine"` → 7, 9) handled naturally by position scanning
- Zero allocations - no intermediate `Vec` needed

### Mission 11 Step 5: Cache Warming Effect in Microbenchmarking 🔍

**Discovery**: Execution order significantly affects µs-scale measurements.

**Experiment**: Compare boolean vs counting DP on same design (`"bwrrrbgbrbwrr"`).

**Results** (dev mode, single measurements):

| Algorithm | Cache State | Time | Performance |
|-----------|-------------|------|-------------|
| Counting v1 | Cold (1st run) | 6.4µs | Baseline |
| Boolean | Warm (2nd run) | 3.9µs | 39% faster |
| Counting v2 | Warm (3rd run) | 4.4µs | 31% faster than v1 |

**Key Findings**:
1. **Cache Warming Penalty**: Same counting algorithm runs 31% faster after cache warm-up (6.4µs → 4.4µs)
2. **Algorithmic Difference**: Boolean (3.9µs) vs Counting-warm (4.4µs) = ~13% difference (OR vs SUM aggregation)
3. **Order Matters**: First measurement was **misleading** - cold cache penalty (2.5µs) > algorithmic difference (0.5µs)

**Microbenchmarking Lessons**:
- Sub-10µs operations vulnerable to environmental noise (cache misses, branch prediction, CPU scaling)
- Execution order can reverse apparent performance relationships
- **Solution**: Use Criterion for production benchmarks:
  - Automatic warmup iterations
  - Statistical analysis (median, outliers, confidence intervals)
  - Noise reduction and regression detection
