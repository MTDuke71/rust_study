### BFS State Tracking Subtlety

**Key Lesson**: State must include BOTH position AND step count.
- Position (5, 5) at step 0 ≠ position (5, 5) at step 2
- Same position reachable via different paths at different steps
- Each leads to different future exploration states

**Why It Matters**:
- Prevents early termination before exploring all reachable positions
- Allows "back-and-forth" movement (Manhattan distance parity)
- Essential for "exactly N steps" problems (not "at most N steps")

### Euclidean Modulo Critical for Infinite Grids

**Wrong Approach** (standard modulo):
```rust
let grid_row = infinite_row % grid_size;  // Negative for negative coords!
arr[grid_row as usize];                    // PANIC: can't cast -3 to usize
```

**Right Approach** (Euclidean modulo):
```rust
let grid_row = infinite_row.rem_euclid(grid_size);  // Always 0 ≤ r < grid_size
arr[grid_row as usize];                              // ✓ Valid array index
```

**Lesson**: Always use `rem_euclid()` for cyclic/wrapping indexing with signed integers.

### Type Safety in Polynomial Fitting

**Issue**: Quadratic coefficients can be negative during calculation.

**Error** (if using usize):
```
error: the trait bound `usize: Neg` is not satisfied
```

**Solution**: Use `i64` for intermediate calculations, cast to `usize` for final result.
```rust
let a = (n0 - 2*n1 + n2) / 2;  // Can be negative
let b = (-3*n0 + 4*n1 - n2) / 2;  // Can be negative
let result = (a * target_n * target_n + b * target_n + c) as usize;
```

**Lesson**: Rust's type system catches mathematical requirements (signed arithmetic needed).
