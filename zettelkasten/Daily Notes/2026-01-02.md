### impl Trait Mental Model
- **NOT dynamic dispatch** - Compiler knows exact type, full optimization possible
- **Use case**: Hiding complex iterator/closure types without runtime cost
- **Limitation**: All return paths must return SAME concrete type
- **vs dyn Trait**: Static (fast, no heap) vs Dynamic (flexible, slower)

### Key Questions Explored
1. **"What is a closure factory?"** - Functions returning functions (higher-order functions)
   - `make_adder(5)` creates function that adds 5
   - `move` keyword transfers ownership into closure so it can outlive parent
   
2. **"Why use `Vec<_>`?"** - Type placeholder for inference
   - `.collect()` needs to know what to build INTO
   - `_` means "you figure out the element type"
   
3. **"Move semantics gotcha"** - Tried to print `numbers` after moving it into function
   - Ownership error: value borrowed after move
   - Solution: Print BEFORE consuming or clone
   - Classic Rust pattern - prevents use-after-free at compile time

4. **"Is function composition good practice?"** - YES!
   - Core functional programming principle
   - Iterator chains (`map`, `filter`) are composition
   - Makes code modular, testable, reusable
   - Zero runtime cost with `impl Fn` return types
