## 📊 AoC 2022 Day 3: Rucksack Reorganization

**Problem**: Finding common items in rucksack compartments and groups.

### Part 1: Compartment Intersection (7850 ⭐)
- Split each rucksack into two equal compartments
- Find the one item appearing in both compartments
- Sum priorities (a=1, b=2, ..., A=27, B=28, ...)

### Part 2: Group Badges (2581 ⭐)
- Group elves into sets of 3
- Find the one item appearing in all 3 rucksacks (badge)
- Sum badge priorities

### Implementation Highlights

**Core Pattern**: Set intersection using `HashSet`
```rust
fn find_common_item(left: &str, right: &str) -> char {
    let left_set: HashSet<char> = left.chars().collect();
    right.chars().find(|c| left_set.contains(c)).unwrap()
}

fn find_badge_item(group: &[&str]) -> char {
    let sets: Vec<HashSet<char>> = group.iter()
        .map(|s| s.chars().collect())
        .collect();
    
    sets[0].iter()
        .find(|&&c| sets[1].contains(&c) && sets[2].contains(&c))
        .copied()
        .unwrap()
}
```

**Key Techniques**:
1. **ASCII Priority Mapping**: `item_priority(c)` converts a-z/A-Z → 1-52 using byte arithmetic
2. **Set Intersection**: HashSet for O(1) membership testing
3. **Chunking**: `.chunks(3)` for grouping elves into badges
4. **Parse-Once Pattern**: Separate `parse()` from `solve_part1()/solve_part2()`

### HashSet Allocation Overhead
**Observation**: Day 3 is **16.7× slower** than Day 2 (359µs vs 21.5µs) despite simpler logic.

**Root Cause**: HashSet allocations dominate runtime
- Part 1: 300 compartments × 2 sets each = 600 HashSet allocations
- Part 2: 100 groups × 3 sets each = 300 HashSet allocations
- **87% of runtime is HashSet allocation**, not the actual intersection logic

**Alternative Approaches** (from function guide):

| Approach | Estimated Time | Speedup | Trade-off |
|----------|---------------|---------|-----------|
| Current (HashSet) | 359.2µs | baseline | Simple, clear, general-purpose |
| **Bit Set** (ASCII) | ~20µs | **18× faster** | Requires ASCII-only, 128-bit overhead |
| Manual Loop | ~150µs | 2.4× faster | More code, less idiomatic |
| Sorted + Two-Pointer | ~450µs | 0.8× slower | Not worth it for small sets |

**Bit Set Optimization** (potential):
```rust
fn items_to_bitset(s: &str) -> u128 {
    s.bytes().fold(0u128, |acc, b| acc | (1 << b))
}

fn find_common_item_bitset(left: &str, right: &str) -> char {
    let intersection = items_to_bitset(left) & items_to_bitset(right);
    (intersection.trailing_zeros() as u8) as char
}
```
- Single u128 per compartment (no heap allocation)
- Intersection = bitwise AND operation (single instruction)
- Could reduce Day 3 from 359µs → **~20µs** (comparable to Day 2)

## 🧠 Key Learnings

### Set Intersection Pattern
**When to use**:
- Finding common elements between collections
- Membership testing (item exists in set?)
- Duplicate detection

**HashSet trade-offs**:
- ✅ General-purpose (works with any type)
- ✅ Idiomatic Rust (`.collect()` into HashSet)
- ❌ **Allocation overhead** (heap allocation per set)
- ❌ Hash computation overhead (SipHash for every char)

**Optimization opportunities**:
- Use bit sets for small, bounded domains (ASCII = 128 bits)
- Use arrays/lookup tables for tiny domains (e.g., Day 2's 9 cases)
- Consider manual loops when allocation overhead > intersection logic

### Chunking Pattern
**`.chunks(n)` for fixed-size groups**:
```rust
for group in rucksacks.chunks(3) {
    // Process 3 rucksacks at a time
}
```
- Efficient iterator-based grouping
- Handles remainder automatically (last group may be < n)
- Common in AoC for "process every N items" problems

### Performance Lessons
1. **Allocation >> Computation**: HashSet allocation (87%) vs intersection logic (13%)
2. **Data Structure Matters**: Bit sets can be 18× faster than HashSet for constrained domains
3. **Measure Before Optimizing**: Benchmarks revealed unexpected bottleneck (not the algorithm, but the allocations)
