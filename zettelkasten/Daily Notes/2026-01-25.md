## 🔧 **Technical Insights**

### Graph Minimum Cut Algorithms
- **Edge Betweenness**: Edges that appear in many shortest paths are likely bottlenecks
- **BFS Approximation**: O(V²×E) to count edge usage vs O(V³) exact all-pairs paths
- **Combination Testing**: Heuristic isn't perfect → validate with C(k,3) combinations
- **Why k=20**: Empirically sufficient to contain the 3 cut edges (could use 10-30)

### BST Deletion Complexity
- **Three Cases**:
  1. **Leaf node**: Simple removal (set parent pointer to None)
  2. **One child**: Splice out node (parent points to child)
  3. **Two children**: Replace with in-order successor (min of right subtree)
- **In-order Successor**: Leftmost node in right subtree maintains BST property
- **Recursive Pattern**: Extract min helper for clean deletion implementation

### Picosecond Benchmarks
- **Day 25 Part 2**: 584 picoseconds = 0.000000584 milliseconds
- **Interpretation**: Pure function call overhead (return static string reference)
- **Comparison**: 689,670,000 ps (Part 1 graph work) vs 584 ps (literal return)

### Edge Betweenness Analysis - Day 25 Optimization ⚡
**Added debug output to understand why the algorithm works so well**

#### Full Input (1495 nodes, 3333 edges):
Top 20 edge betweenness values revealed:
1. `("gpj", "tmb")` → **1488 paths** ✓ (cut edge)
2. `("mtc", "rhh")` → **1462 paths** ✓ (cut edge)
3. `("njn", "xtx")` → **1421 paths** ✓ (cut edge)
4. `("fgg", "njq")` → **1178 paths** ← **BIG DROP (243 fewer!)**
5. Remaining edges: ~1137-1178 paths

**Key Insight**: The 3 cut edges are "superhighways" carrying **243+ more paths** than any other edge!
- The algorithm works because these bottleneck edges stand out dramatically
- Gap of 243 paths between rank 3 and rank 4 is massive
- Search space reduction: C(3333,3) ≈ 6 billion → C(20,3) = 1,140 combinations

#### Example Input (15 nodes):
Top 4 edges showing why top-20 is needed:
1. `("jqt", "nvd")` → **13 paths** ✓ (cut edge)
2. `("hfx", "pzl")` → **12 paths** ✓ (cut edge)
3. `("bvb", "cmg")` → **11 paths** ✓ (cut edge)
4. `("lsr", "pzl")` → **11 paths** ✗ **TIE!** (same component)

**Critical Discovery**: Ranks 3 and 4 are **tied at 11 paths**!
- This proves why we need combination testing, not just taking top 3
- Betweenness heuristic identifies candidates but ties require validation
- Testing C(20,3) combinations handles ambiguity in the ranking
