## Key Concepts Mastered

### 1. Future Trait
```rust
pub trait Future {
    type Output;
    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
}

enum Poll<T> {
    Ready(T),   // Future completed
    Pending,    // Not ready, will be woken later
}
```

### 2. Async/Await Syntax
```rust
// async fn returns impl Future<Output = T>
async fn fetch_data() -> String {
    tokio::time::sleep(Duration::from_secs(1)).await;
    String::from("Data")
}

// Futures are LAZY - nothing happens until .await
let future = fetch_data();  // Creates future, doesn't execute
let data = future.await;    // NOW it executes
```

### 3. Concurrent Execution
```rust
// Wait for multiple futures concurrently
let (a, b, c) = tokio::join!(task_a(), task_b(), task_c());

// Race futures - first to complete wins
tokio::select! {
    data = fetch_cache() => use_cache(data),
    data = fetch_network() => use_network(data),
}
```

### 4. Stream Trait
```rust
// Stream = async Iterator
// poll_next() -> Poll<Option<Item>>

while let Some(item) = stream.next().await {
    process(item).await;
}
```

### 5. Tasks vs Threads Decision
```
┌─────────────────────┬─────────────────────┐
│ Parallelism needed? │ → Use threads       │
│ Concurrency needed? │ → Use async         │
│ Both needed?        │ → Combine them!     │
└─────────────────────┴─────────────────────┘

Memory comparison:
• Thread: ~2MB stack, OS-managed
• Task: ~few KB, runtime-managed
• Can spawn millions of tasks, but not threads!
```

### 6. Hybrid Pattern (Listing 17-42)
```rust
// Thread for CPU work, async for I/O
let (tx, mut rx) = mpsc::channel(16);

// Thread sends using blocking_send
thread::spawn(move || {
    tx.blocking_send(value).unwrap();
});

// Async receives
while let Some(msg) = rx.recv().await {
    process(msg);
}
```

## Common Pitfalls Avoided

1. **Blocking in async context** - Use `tokio::time::sleep`, not `std::thread::sleep`
2. **Forgetting .await** - Futures are lazy, must await to execute
3. **Holding Mutex across .await** - Use `tokio::sync::Mutex` instead
4. **Not handling cancellation** - Dropping futures cancels them

## Comparison with Ch16 (Threading)

| Aspect | Ch16 Threads | Ch17 Async |
|--------|-------------|------------|
| **Best For** | CPU-bound work | I/O-bound work |
| **Scalability** | ~1000s of threads | Millions of tasks |
| **Memory** | ~1-2MB per thread | ~few KB per task |
| **Scheduling** | Preemptive (OS) | Cooperative (runtime) |
| **Blocking** | Can block safely | Must not block! |
| **Primitives** | Mutex, channels, Arc | async/await, join!, select! |
