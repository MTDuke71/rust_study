## 📋 **Step 1: Understanding OpenAPI and Documentation-as-Code (20 minutes)**

### **1.1 The Documentation Problem**

**Traditional API Documentation** (Manual, separate):
```markdown
# API Documentation

## Create Union-Find Instance
- **URL**: POST /api/v1/unionfind
- **Body**: { "size": number }
- **Response**: { "id": string, "size": number, "created_at": string }
- **Errors**: 400 if size invalid

❌ Problems:
- Documentation separate from code
- Gets out of sync quickly
- No interactive testing
- Manual updates error-prone
```

**OpenAPI/Swagger** (Generated from code):
```rust
#[utoipa::path(
    post,
    path = "/api/v1/unionfind",
    request_body = CreateRequest,
    responses(
        (status = 201, description = "Instance created successfully", body = CreateResponse),
        (status = 400, description = "Invalid size parameter")
    )
)]
async fn create_instance(...) -> Response {
    // Code and docs in same place!
}

✅ Benefits:
- Documentation IN the code
- Auto-generates interactive Swagger UI
- Type-safe: Rust types → JSON schemas
- Always in sync (compile-time checked)
```

### **1.2 OpenAPI Specification Overview**

**OpenAPI** (formerly Swagger) is a standard for describing REST APIs:

```yaml
# OpenAPI spec (generated by Utoipa from your Rust code)
openapi: 3.0.0
info:
  title: Union-Find REST API
  version: 1.0.0
paths:
  /api/v1/unionfind:
    post:
      summary: Create new Union-Find instance
      requestBody:
        required: true
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/CreateRequest'
      responses:
        '201':
          description: Instance created successfully
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/CreateResponse'
```

**Swagger UI**: Browser-based tool that reads OpenAPI spec and creates:
- Interactive API documentation
- "Try it out" buttons to test endpoints
- Schema validation and examples
- Authentication testing
- Real-time request/response preview

### **1.3 Utoipa: Rust OpenAPI Generator**

**Utoipa** is a Rust library that:
1. Uses macros to annotate your code
2. Generates OpenAPI 3.0 spec at compile time
3. Provides Swagger UI integration for Axum

**Key macros**:
- `#[derive(ToSchema)]` - Generate JSON schema from struct
- `#[utoipa::path]` - Document endpoint handler
- `#[derive(OpenApi)]` - Generate complete OpenAPI spec
- `#[schema(...)]` - Add examples, descriptions, validation rules

**Architecture**:
```
Your Rust Code (with Utoipa annotations)
           ↓
    Compile-time macro expansion
           ↓
    OpenAPI 3.0 JSON specification
           ↓
    Swagger UI (interactive documentation)
```

### **1.4 REQ-10 Requirements Breakdown**

**REQ-10**: REST API endpoints shall provide OpenAPI documentation with Swagger UI

**Technical Requirements**:

## 📋 **Step 3: Annotating Request/Response Models (30 minutes)**

### **3.1 Understanding `#[derive(ToSchema)]`**

**ToSchema** tells Utoipa to generate JSON schema from your Rust struct:

```rust
use utoipa::ToSchema;

// Before (Day 10):
#[derive(Debug, Serialize, Deserialize)]
pub struct CreateRequest {
    pub size: usize,
}

// After (Day 11): 
#[derive(Debug, Serialize, Deserialize, ToSchema)]
pub struct CreateRequest {
    #[schema(example = 10, minimum = 1)]
    pub size: usize,
}
```

**Generated OpenAPI schema**:
```json
{
  "CreateRequest": {
    "type": "object",
    "required": ["size"],
    "properties": {
      "size": {
        "type": "integer",
        "format": "int64",
        "minimum": 1,
        "example": 10
      }
    }
  }
}
```

### **3.2 Schema Attributes**

**Common `#[schema(...)]` attributes**:

| Attribute | Purpose | Example |
|-----------|---------|---------|
| `example` | Example value for docs | `#[schema(example = 42)]` |
| `minimum` | Minimum value (numbers) | `#[schema(minimum = 0)]` |
| `maximum` | Maximum value (numbers) | `#[schema(maximum = 100)]` |
| `min_length` | Minimum string length | `#[schema(min_length = 1)]` |
| `pattern` | Regex validation | `#[schema(pattern = "^[a-z]+$")]` |
| `description` | Field description | `#[schema(description = "User ID")]` |
| `nullable` | Can be null | `#[schema(nullable)]` |

### **3.3 Annotate All Request Models**

**File: `models.rs`**

```rust
use serde::{Deserialize, Serialize};
use utoipa::ToSchema;
use uuid::Uuid;
use chrono::{DateTime, Utc};

/// Request body for creating a new Union-Find instance
#[derive(Debug, Serialize, Deserialize, ToSchema)]
pub struct CreateRequest {
    /// Number of elements in the set (must be > 0)
    #[schema(example = 10, minimum = 1)]
    pub size: usize,
}

/// Request body for union operation
#[derive(Debug, Serialize, Deserialize, ToSchema)]
pub struct UnionRequest {
    /// First element to union
    #[schema(example = 3, minimum = 0)]
    pub element1: usize,
    
    /// Second element to union
    #[schema(example = 7, minimum = 0)]
    pub element2: usize,
}

/// Query parameters for find operation
#[derive(Debug, Deserialize, ToSchema)]
pub struct FindRequest {
    /// Element to find the root of
    #[schema(example = 5, minimum = 0)]
    pub element: usize,
}

/// Query parameters for connected check
#[derive(Debug, Deserialize, ToSchema)]
pub struct ConnectedRequest {
    /// First element to check
    #[schema(example = 3, minimum = 0)]
    pub element1: usize,
    
    /// Second element to check
    #[schema(example = 7, minimum = 0)]
    pub element2: usize,
}
```

### **3.4 Annotate All Response Models**

```rust
/// Response after creating a Union-Find instance
#[derive(Debug, Serialize, ToSchema)]
pub struct CreateResponse {
    /// Unique identifier for the instance
    pub id: Uuid,
    
    /// Number of elements in the set
    pub size: usize,
}

/// Statistics about a Union-Find instance
#[derive(Debug, Serialize, ToSchema)]
pub struct StatsResponse {
    /// Total number of elements
    pub total_elements: usize,
    
    /// Number of disjoint sets
    pub num_components: usize,
}

/// Result of find operation
#[derive(Debug, Serialize, ToSchema)]
pub struct FindResponse {
    /// The element that was queried
    #[schema(example = 5)]
    pub element: usize,
    
    /// Root element of the set
    #[schema(example = 3)]
    pub root: usize,
}

/// Result of union operation
#[derive(Debug, Serialize, ToSchema)]
pub struct UnionResponse {
    /// Whether the elements were successfully merged (false if already connected)
    pub merged: bool,
    
    /// The new root of the set
    pub root: usize,
}

/// Result of connected check
#[derive(Debug, Serialize, ToSchema)]
pub struct ConnectedResponse {
    /// Whether elements are in the same set
    pub connected: bool,
}

/// Error response structure
#[derive(Debug, Serialize, ToSchema)]
pub struct ErrorResponse {
    /// Error code
    pub code: String,
    
    /// Human-readable error message
    pub message: String,
}
```

**Note**: `ToSchema` is only imported in `models.rs` where the structs are defined. You don't need to import it in `handlers.rs`.

## 📋 **Step 5: Generating OpenAPI Specification (20 minutes)**

### **5.1 Create OpenAPI Struct**

Add new module or update `main.rs`:

```rust
use utoipa::OpenApi;
use utoipa_swagger_ui::SwaggerUi;

// Import all your handlers and models
use crate::handlers::*;
use crate::models::*;

/// OpenAPI specification for Union-Find REST API
#[derive(OpenApi)]
#[openapi(
    paths(
        crate::handlers::create_instance,
        crate::handlers::union_elements,
        crate::handlers::find_element,
        crate::handlers::check_connected,
        crate::handlers::get_stats,
        crate::handlers::delete_instance,
    ),
    components(
        schemas(
            CreateRequest,
            CreateResponse,
            UnionRequest,
            UnionResponse,
            FindRequest,
            FindResponse,
            ConnectedRequest,
            ConnectedResponse,
            StatsResponse,
            ErrorResponse
        )
    ),
    tags(
        (name = "Union-Find Management", description = "Lifecycle operations for Union-Find instances"),
        (name = "Operations", description = "Core Union-Find operations")
    ),
    info(
        title = "Mission 10 Union-Find API",
        version = "1.0.0",
        description = "REST API for Mission 10 Union-Find implementation with path compression and union by rank optimizations"
    )
)]
pub struct ApiDoc;
```

**Breakdown**:
- `info(...)` - API metadata (title, version, description)
- `paths(...)` - List all handler functions
- `components.schemas(...)` - List all request/response models
- `tags(...)` - Group endpoints in Swagger UI

### **5.2 Understanding OpenAPI Generation**

**At compile time**, Utoipa:
1. Reads `#[utoipa::path]` annotations from handlers
2. Reads `#[derive(ToSchema)]` from models
3. Generates complete OpenAPI 3.0 JSON specification
4. Embeds spec in binary (no runtime parsing!)

**At runtime**, you call the generated method:
```rust
ApiDoc::openapi()  // Returns complete OpenAPI spec as JSON
```

**In practice** (as shown in Section 6.1), you call this inline when setting up Swagger UI in `main.rs`:
```rust
.merge(SwaggerUi::new("/swagger-ui")
    .url("/api-docs/openapi.json", ApiDoc::openapi()))  // ← Called here
```

You don't need to store it in a separate variable; the `SwaggerUi` integration consumes the spec directly.

## 📋 **Step 6: Integrating Swagger UI (15 minutes)**

### **6.1 Add Swagger UI Route**

Update your router in `main.rs`:

```rust
use axum::{
    Router,
    routing::{post, get, delete},
};
use utoipa_swagger_ui::SwaggerUi;

#[tokio::main]
async fn main() -> Result<()> {
    // Existing state setup
    let app_state = AppState {
        instances: Arc::new(RwLock::new(HashMap::new())),
    };

    // Build router with all endpoints
    let app = Router::new()
        .route("/health", get(health_check))
        .merge(SwaggerUi::new("/swagger-ui").url("/api-docs/openapi.json", ApiDoc::openapi()))
        .nest("/api/v1", handlers::routes())
        .layer(CorsLayer::permissive())
        .with_state(app_state);

    // Start server (existing code)
    let addr = SocketAddr::from(([127, 0, 0, 1], 8080));
    println!("🚀 Server running on http://{}", addr);
    println!("📖 API Documentation: http://{}/swagger-ui", addr);
    
    axum::serve(listener, app).await?;
    Ok(())
}
```

### **6.2 Understanding SwaggerUi::new()**

```rust
SwaggerUi::new("/swagger-ui")            // Swagger UI accessible at this path
    .url("/api-docs/openapi.json",       // OpenAPI spec served here
         ApiDoc::openapi())              // Generated spec from annotations
```

**What this creates**:
- `http://localhost:8080/swagger-ui` - Interactive Swagger UI
- `http://localhost:8080/api-docs/openapi.json` - Raw OpenAPI spec (JSON)

**Why merge()**?
```rust
Router::new()
    .route("/api/v1/...", ...)  // Your API routes
    .merge(SwaggerUi::new(...))  // Adds Swagger routes alongside
```

`merge()` combines two routers, so Swagger UI doesn't interfere with your API paths.

## 📋 **Step 10: Documentation Best Practices (10 minutes)**

### **10.1 Writing Good Descriptions**

**Bad**:
```rust
#[utoipa::path(
    post,
    path = "/api/v1/unionfind",
    responses(
        (status = 201, description = "Success", body = CreateResponse)
    )
)]
```

**Good**:
```rust
/// Create a new Union-Find instance with specified size
#[utoipa::path(
    post,
    path = "/api/v1/unionfind",
    responses(
        (status = 201,
         description = "Union-Find instance created successfully with unique UUID",
         body = CreateResponse)
    )
)]
```

**Guidelines**:
- Use full sentences in descriptions
- Explain what success means specifically
- Document error conditions clearly
- Include examples when helpful

### **10.2 Schema Documentation**

```rust
#[derive(Debug, Serialize, Deserialize, ToSchema)]
pub struct UnionRequest {
    /// First element index (0-based, must be < size)
    #[schema(
        example = 3,
        minimum = 0,
        description = "Zero-based index of first element to union"
    )]
    pub element1: usize,
    
    /// Second element index (0-based, must be < size)
    #[schema(
        example = 7,
        minimum = 0,
        description = "Zero-based index of second element to union"
    )]
    pub element2: usize,
}
```

**Good schema docs**:
- Explain units (0-based index)
- Document constraints (must be < size)
- Provide realistic examples
- Clarify ambiguous terms

### **10.3 Organizing with Tags**

For larger APIs with many endpoints:

```rust
#[utoipa::path(
    // ... config
    tag = "admin"  // Group admin endpoints
)]
pub async fn admin_reset(...) {}

#[utoipa::path(
    // ... config
    tag = "unionfind"  // Group union-find operations
)]
pub async fn create_instance(...) {}
```

Swagger UI groups endpoints by tag for easy navigation.

### **10.4 Documentation Maintenance**

**Keep docs in sync**:
1. ✅ Documentation IN code (not separate file)
2. ✅ Compiler verifies schema types match handlers
3. ✅ Changes to handler signature break compilation
4. ✅ Forced to update annotations

**Documentation as tests**:
- If handler changes, docs must change
- If docs are wrong, integration tests fail
- Swagger UI testing validates docs match behavior

## 🔍 **Troubleshooting Common Issues**

### **Issue: "Cannot find derive macro `ToSchema`"**

**Fix**: Add import
```rust
use utoipa::ToSchema;
```

### **Issue: "Schemas not showing in Swagger UI"**

**Fix**: Ensure all types listed in `components.schemas(...)`:
```rust
#[derive(OpenApi)]
#[openapi(
    components(
        schemas(
            CreateRequest,      // ← All request types
            CreateResponse,     // ← All response types
            ErrorResponse,      // ← Don't forget error type!
        )
    )
)]
```

### **Issue: "Path parameters not documented"**

**Fix**: Add `params(...)` to `#[utoipa::path]`:
```rust
#[utoipa::path(
    get,
    path = "/api/v1/unionfind/{id}/stats",
    params(
        ("id" = Uuid, Path, description = "Instance UUID")
    ),
    // ...
)]
```

### **Issue: "Query parameters showing as path parameters"**

**Fix**: Specify `Query` in params:
```rust
params(
    ("id" = Uuid, Path, description = "Instance UUID"),
    ("element" = usize, Query, description = "Element index")  // ← Query not Path
)
```

### **Issue: "Swagger UI shows but endpoints missing"**

**Fix**: Ensure handlers listed in `paths(...)`:
```rust
#[derive(OpenApi)]
#[openapi(
    paths(
        handlers::create_instance,
        handlers::delete_instance,
        // ... all 6 handlers
    )
)]
```

## 📚 **Key Concepts Summary**

### **OpenAPI/Swagger**
- **OpenAPI**: Standard specification for REST APIs (JSON/YAML)
- **Swagger UI**: Interactive documentation tool that reads OpenAPI specs
- **Benefits**: Documentation always in sync, interactive testing, client generation

### **Utoipa Macros**
- `#[derive(ToSchema)]` - Generate JSON schema from struct
- `#[utoipa::path]` - Document endpoint handler
- `#[derive(OpenApi)]` - Generate complete OpenAPI spec
- `#[schema(...)]` - Add examples, validation, descriptions

### **Documentation as Code**
- Documentation IN code (not separate)
- Compiler-checked (types must match)
- Auto-generated (no manual maintenance)
- Executable specification (Swagger UI tests docs)

### **Three-Layer Documentation**
1. **Code level**: Handler implementations with business logic
2. **Annotation level**: `#[utoipa::path]` and `#[schema]` attributes
3. **Generated level**: OpenAPI JSON served to Swagger UI
